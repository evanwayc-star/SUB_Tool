# SUB Tool — 多軌時間軸上字幕工具

上字幕編輯器，同一份 `dist/index.html` 同時支援**網頁版**與 **Electron 桌面版**。

> 目前正式版本：**v4.6.3**（2026-07-23）
> （本專案已完成 100% 全檔案架構註釋與維護鐵律保護網）

## 功能摘要

- **多軌字幕時間軸**：拖曳區塊調整起訖、換軌、磁吸對齊；`I`/`O` 上字幕
- **字幕樣式系統**：字級／座標／角度／對齊／字色／框線／陰影／底色／字距行距／**直書**／
  自備字型，可**逐句覆蓋**，可存成**常用樣式**跨專案套用。預覽＝mpv＝匯出燒錄**三路一致**
- **在播放器上直接拖字幕**定位與旋轉；安全框（100%／90%／80%＋中心線）與可切換的**時間碼監看浮水印**
- **影片序列 / 多視訊軌**：切割、修剪、疊層、子母畫面、透明度、淡入淡出與**軌間溶接**；可解除影音連結，讓影片與原音各自剪輯
- **圖片素材疊加**：PNG/JPG 等圖片會成為獨立視訊素材，可在播放器直接拖移、四角等比縮放，並保留位置、大小與片段時間；匯出時以靜態畫面完整覆蓋該片段長度
- **WebCodecs 自寫預覽引擎**：多軌**即時合成**預覽（與匯出一致），串流式 demux 不限片長
- **專案音訊路由**：專案可設 2／4／6／8／10／16／18 或自訂總聲道；每個素材獨立對應來源聲道到輸出 bus，支援 Mono、Stereo、5.1 與純多聲道 WAV
- **匯出影片 / WAV**：影像與音訊一律從**母素材**解碼，絕不使用 Proxy 或播放快取；ProRes 422 HQ（24-bit PCM 母帶）或 MP4（H.264 + 依聲道數配置 AAC）、GPU 編碼、字幕燒入；WAV 保留每條專案 bus 為獨立 mono 聲道
- **交付時間碼**：播放器的 `TC` 僅供監看；影片匯出可另選「壓入時間碼浮水印」，由輸出範圍的原始時間碼開始計算
- **字幕檢查**：可找出明確簡體字、繁簡共用字與其他非繁中／英文／數字／符號字元；僅含共用字的句子以黃色提示人工確認
- JKL 穿梭輪（最高 5×）、`←/→` 逐格定位、可自訂快捷鍵（支援匯出／匯入）
- 匯入 / 匯出：SRT、ASS/SSA、Adobe Encore 時碼、純文字、XLSX
- FPS 自動偵測（23.976 / 24 / 25 / 29.97 DF/NDF / 30）
- 多音軌混音器（以**專案輸出軌**為主；獨奏 / 靜音 / 逐聲道電平表）
- 桌面版：MXF / MKV / AVI 等非原生格式（系統 ffmpeg）、mpv 秒開、媒體快取

## 快速開始

### 前置需求

- [Node.js](https://nodejs.org) 18+
- [ffmpeg](https://ffmpeg.org)（桌面版 MXF / 多音軌需要；放入 PATH 或 `C:\Program Files\FFMPEG\bin\`）

### 網頁版

```bash
npm install       # 第一次安裝
npm run build     # 打包成 dist/index.html
# 開啟 dist/index.html（或雙擊 啟動工具.bat 自動執行上述步驟）
```

### 桌面版

```bash
npm install          # 第一次安裝
npm run electron     # build + 啟動 Electron
# 或雙擊 啟動桌面版.bat
```

### 開發模式（熱更新）

```bash
# 終端機 1
npm run dev
# 終端機 2
npm run electron:dev    # 連 dev server + 開 DevTools
```

## 打包安裝檔（exe）

```bash
npm run dist    # electron-builder → release/SUB Tool Setup 4.6.2.exe
```

## 給接手的工程師

- **發版流程**：`npm run lint && npm test && npm run build` → 桌面版真機驗證 → 版號 +1（`package.json` 與 lockfile）→
  同步 README 與全部 `docs/` → 補變更紀錄 → `npm run dist` → commit/push → 發佈附有 Setup `.exe` 的 GitHub Release。詳見 [開發說明.md](docs/開發說明.md)。
- **單元測試涵蓋純邏輯與專案資料完整性**（時碼、格式、工具、音訊路由、圖片序列、輸出範圍與字幕文字檢查）。UI 與媒體行為一律用桌面版
  Electron 視窗驗證——方法與兩個「驗證方法本身出錯」的真實案例都寫在開發說明裡。
- **變更紀錄請寫「為什麼」和「怎麼驗的」**，不要只寫「修了 X」。這份習慣讓好幾個坑
  （字型家族名、filtergraph 跳脫、CSS 蓋掉 `[hidden]`）沒有被重踩。
