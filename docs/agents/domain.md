# 領域文件設定

本專案只有一個 context。工程 skill 探索前先讀根目錄的 [CONTEXT.md](../../CONTEXT.md)，再讀 [docs/adr/](../adr/) 中與變更區域相關的決策；共用規則入口是 [AGENTS.md](../../AGENTS.md)。

## 文件位置

| 資料 | 唯一位置 | 使用方式 |
|---|---|---|
| 領域詞彙 | `CONTEXT.md` | 定義概念；Issue、提案、測試與假說沿用同一名稱 |
| 架構決策 | `docs/adr/NNNN-決策標題.md` | 記錄理由、代價與推翻條件，修改前核對既有決策 |

兩者都已存在；本 repo 沒有 `CONTEXT-MAP.md`，也不另設 `src/<context>/docs/adr/`。

## 何時補充

真正釐清新詞或做出架構決策時，使用 `/domain-modeling` 更新對應文件。尚未解決的問題先列為問題，不預建空白 ADR，也不把實作教學放進詞彙表。

新概念尚無定義時，先確認它是否只是既有詞彙的別名；有實質缺口才補定義。三個維護工具共享用語，不各自發明同義名稱。

提案與既有 ADR 衝突時，指出實際編號、衝突內容及值得重開的證據，不默默改寫已採用決策。新增文件類別時，同步更新 [AGENTS.md 文件職責](../../AGENTS.md#3-文件職責不要把內容寫到錯的檔案)與 README 入口。
