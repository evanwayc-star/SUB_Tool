# SUB Tool — 技術架構說明

> 對應版本：v4.6.1｜最後更新：2026-07-22
>
> **新進工程師請先讀 §0「鐵律」**——那些是違反後會【靜默】壞掉的不變量（畫面看起來正常、
> 匯出卻是錯的），本專案絕大多數的 bug 都出在那幾條上。

## 0. 鐵律（Invariants）

> 這一節不是風格建議，是**血淚**。每一條後面都附了「違反時實際發生過什麼」。

### 0.1 三路一致：預覽 ＝ mpv ＝ 匯出燒錄

字幕有三條渲染路徑，**必須長得一樣**：

| 路徑 | 實作 | 進入點 |
|------|------|--------|
| HTML 預覽 | `#videoSub` 疊層 | `app.js renderVideoSub()` |
| mpv（MXF 等非原生格式） | libass | `app.js refreshMpvSubs()` → `subSet(toASSFromState())` |
| 匯出燒錄 | ffmpeg `ass` 濾鏡 | `subio.js _runExportVideo()` → 同一份 `toASSFromState()` |

**三路都只准吃 `substyle.js effStyle()` 的結果。** 新增任何樣式欄位，必須同時接
`styleToCss()`（HTML）與 `styleToAssStyleLine()`／`cueAssTags()`（ASS）。

> 違反案例：v4.23 加直書時只做了 HTML 的 `writing-mode`，ASS 端留著「整段逐字疊成一柱」的
> 第一版 → 預覽 3 列、匯出 1 列 27 字衝出畫面（v4.29.3 才修）。

### 0.2 縮放基準是「畫面高 ÷ PlayResY」，不是寬

ASS 的 **Fontsize／Outline／Shadow 全部相對 `PlayResY`**（`ScaledBorderAndShadow: yes`）。
HTML 預覽的 `ratio` 必須用 `stageH / ASS_PLAY_RES.y`。

> 違反案例：舊版用 `stageW / PlayResX`。16:9 時寬高等比例所以剛好對得上，**2.35:1 的片
> 字級大 33%**（實測佔畫面高 9.9% vs ASS 的 7.41%），而且與匯出不符。使用者回報是
> 「不同檔案格式大小不同」——其實與格式無關，是比例（v4.31.0 修）。

`ASS_PLAY_RES`（`substyle.js`）是**預覽與 `toASSFromState` 共用的唯一來源**，不可各寫一份。

### 0.3 ASS 的 Fontname 是「字型檔內部的家族名」，不是資料夾名

UI 顯示的是使用者自取的**資料夾名**（`font/台北黑體/`），libass／fontconfig 只認**檔案內部的
家族名**（`Taipei Sans TC Beta`）。必須經 `substyle.assFontName()` 轉換。

> 違反案例：v4.24～v4.29.2 直接把資料夾名填進 ASS → libass 配不到 → **靜默**退回微軟正黑體。
> 七個字型全中，預覽正確、匯出全錯，毫無錯誤訊息。更陰的是「標楷體」：資料夾名剛好也是系統
> 既有字型 → 不算退回、卻換成了微軟標楷體。

判斷字重要讀 **OS/2 的 `usWeightClass`**，不能看 name table 的 subfamily：CJK 字型每個字重
各自是一個「家族」、subfamily 一律寫 `Regular`（`Noto Sans CJK TC Black` 的 nameID2 也是
`Regular`）→ 分不出來（v4.31.1）。

### 0.4 filtergraph 的 Windows 路徑要跳脫【兩層】

`-filter_complex` 裡的選項值若含磁碟機冒號，字面上必須是 `C\\:/...`（兩個反斜線）。
filtergraph 先拆選項、選項值再拆一次。

> 違反案例：`fontsdir=C\:/...`（單反斜線）→ ffmpeg 把 `:` 當選項分隔符 → **整條 filterchain
> 解析失敗 → 完全無法匯出影片**。此參數只在 `font/` 存在時才加，所以 v4.27.0 把字型打進安裝包
> 之後，安裝版的匯出才開始壞（v4.31.2 修）。
>
> **這個坑騙過人**：手動在 shell 跑 ffmpeg 也會撞到同一個錯，很容易誤判成「PowerShell／MSYS
> 吃掉跳脫字元」。用 `spawn`（無 shell 介入）重測才能確認是程式的問題。

### 0.5 時間域：對外一律「時間軸時間」，播放器內部一律「來源時間」

`source = timeline - clip.offset + clip.in`。轉換**只准**發生在 `sequence.js` / `media.js` 的序列層。

### 0.6 「有產出」不等於「對」

驗證必須看**內容**，不是看有沒有報錯：
- 匯出 → 抽格出來看字幕真的燒進去、字型真的是選的那個。
- 字型 → 讀 libass 的 `fontselect:` 判定（**退回旗標 1 ＝ 沒配到**），不能只看有沒有 crash。
- 直書／座標 → 把 ASS 燒成 PNG，與預覽的 DOM 量測逐項比對。

> 反例：v4.27／v4.29.3 兩次「修好字型」都只驗了 libass 配對，從沒跑過應用程式自己的匯出 →
> 匯出其實整個是壞的，過了四個版本才被使用者發現。
>
> 另一個反例：拿「有／無 fontsdir 兩張圖比對」判斷字型有沒有生效——但那台機器七個字型全都
> 已安裝，兩邊都找得到、圖當然一樣，測了等於沒測。

### 0.7 「有沒有顯示」只能看 computed style，不能看屬性

### 0.8 音訊素材、專案 bus 與匯出聲道不可混為一談

每個影音／音訊素材保有自己的來源聲道與時間軸 placement；`audio-routing.js` 再把來源聲道映射到**專案輸出 bus**。混音器、影片輸出與 WAV 輸出都必須讀同一份編譯後的 audio plan，不能直接把某個素材的 Web Audio track 順序當輸出順序。

解除影音後產生的音訊必須有自己的 `AudioElement` 群組與 placement，不能和影片容器共用 seek 位置。MXF／部分 MOV 不可直接交給 Chromium `<audio>`，應使用 ffmpeg 已抽取的逐聲道快取；`preferCache` 必須寫入專案，以便重開後仍走同一條可靠路徑。

### 0.9 靜態圖片也是時間軸片段，不是播放器的一格畫面

圖片 clip 必須保留 `type: 'image'`、`in / out / offset / vtrack` 與自身的 `scale / posX / posY`，並在**預覽、專案儲存、Undo／Redo 與匯出**各路徑都完整傳遞。匯出主程序看到 `type: 'image'` 才能對 ffmpeg 輸入加 `-loop 1`；若只傳圖片路徑，它只會解一格，畫面看似「輸出只剩開頭第一格」。

mpv 是 OS 層原生子視窗，主視窗 DOM 不能直接放到它上面。需要可操作的圖片疊層時，必須使用**透明 guide BrowserWindow**：guide 只負責顯示圖片與轉送白名單化的 pointer 座標，實際幾何修改仍只在 renderer 的 `app.js` 完成。不要讓 guide 無條件攔截整片播放器，否則字幕拖曳、播放控制與右鍵選單都會失效。

**判斷元素在畫面上看不看得見，一律用 `getComputedStyle(el).display` 或量
`getBoundingClientRect()`。** 讀 inline `style.display`、讀 `el.hidden`、讀 canvas 像素
——這三種都測不到「有沒有真的顯示在螢幕上」。

| 案例 | 當時檢查的 | 為什麼測了等於沒測 |
|------|-----------|-------------------|
| v4.33.2 預覽畫布全黑 | `getImageData` 讀得到像素；inline `style.display` 是 `''` | **隱藏的 canvas 照樣讀得到像素**；`''` 只代表沒有 inline 值，computed 其實是 `none`（`.preview-canvas` 的 CSS 基礎規則就是 `display:none`） |
| v4.34.1 編輯提示列藏不掉 | `el.hidden === true` | `.ts-line{display:flex}` 是**作者規則**，蓋過 UA 樣式表的 `[hidden]{display:none}`；屬性是 true，畫面上照樣看得到 |

推論：**要用 `el.hidden` 藏一個自己設過 `display:` 的元素，必須補一條
`.那個class[hidden]{display:none}`**，否則藏不掉。

另外「同一列」不要用盒頂座標比——不同高度的元素垂直置中後盒頂本來就不同（分隔線 15px vs
下拉 23px 差 4px）。比**垂直中心**，或量整行高度確認沒換行。

## 1. 專案概覽

本專案採 **Vite + 原生 ES 模組**（無框架），以 `vite-plugin-singlefile` 打包成**單一 HTML**
（JS/CSS 內嵌），同時支援網頁版與 Electron 桌面版。共 **31 個 ES 模組**，以「事件匯流排 +
單向依賴」解耦。

Electron 端另有主行程（`electron/main.js`，約 1240 行）負責 ffmpeg／ffprobe／mpv、檔案對話框、
路徑白名單與字型掃描——見 `Electron_維護手冊.md`。

## 3. 各模組詳細說明

### `app.js`（協調層）

唯一訂閱 `events.js` 事件的模組。不暴露公開 API，只作「監聽 → 呼叫對應函式」。

| 函式 | 說明 |
|------|------|
| `renderAll()` | 全量重繪：renderSubList + drawTimeline + renderVideoSub + 播放頭 |
| `renderVideoSub()` | 更新 `#videoSub` 疊層（依播放點篩選 + escapeHTML） |
| `onDurationKnown()` | 媒體載入完成：`_firstLoad` 為真時 `zoomFitVideo()` 自動縮放；之後條件式縮放 |
| `resetProject()` | 清空 State、重置歷史、重置 `_firstLoad`（新專案流程） |
| `zoomFitVideo()` | 縮放時間軸以完整顯示影片長度（或已建字幕範圍） |
| `doAction(name)` | 集中指令分派（open-media、add-track、mixer、export 等） |
| `ensurePlayheadVisible()` | 播放點超出視窗時自動捲動 |
| `refreshMpvSubs()` | mpv 模式：字幕變動時重建 .ass 餵給 mpv（防抖 100ms） |
| `rafLoop()` | `requestAnimationFrame` 主迴圈：播放中更新時碼/seekBar/波形/電平表 |
| `init()` | 瀏覽器模式初始化（含 `ensureTrackCount(1)` 確保預設軌道存在） |
| `initDesktop()` | Electron 模式初始化（IPC 狀態查詢、桌面功能接線） |

### `time.js`（時碼換算）

| 函式 | 說明 |
|------|------|
| `fmtClock(s)` | 秒 → `00:00:00.000`（UI 顯示） |
| `secToSRT(s)` | 秒 → SRT 時碼（`,` 分隔毫秒） |
| `secToASS(s)` | 秒 → ASS 時碼（`.` 分隔百分秒） |
| `encoreParts(s,fps,df)` | 秒 → 時碼分量 `{hh,mm,ss,ff}`（**唯一**換算來源，`secToEncore`/時間軸刻度共用） |
| `secToEncore(s,fps,df)` | 秒 → Encore 時碼（H:M:S:F），支援 SMPTE 29.97 Drop-frame |
| `encoreToSec(t,fps,df)` | Encore 時碼 → 秒（Drop-frame 反運算） |
| `snapTimeToFrame(t,fps,df)` | 秒數對齊最近影格邊界（**唯一**影格格網） |

> **FPS / 時碼一致性**：播放器時碼、字幕列表、時間軸刻度、播放點如何永遠對齊（含 29.97 NDF 漂移、逐格、mpv 沉降等踩雷與修法），見 [`FPS_時碼一致性.md`](FPS_時碼一致性.md)。程式碼關鍵點以 `FPS-SYNC` 標記，可全域搜尋。

### `tcparse.js`（時碼輸入解析）

`parseTimecodeInput(str) → 秒`

支援格式：
- 完整時碼：`01:23:45:12`、`01:23:45;12`（DF）
- 緊湊數字：`12345` → 由右至左解析為 格/秒/分/時
- 相對偏移：`+100` / `-100`（由 `subtitles.js` 處理正負號前置）

### `state.js`（全域狀態）

`State` 物件包含所有可變資料：

```js
State = {
  cues: [],          // [{id, start, end, text, track, timed}]
  tracks: [],        // [{name, visible, fontScale, posPct, align, locked, color}]
  notes: [],         // [{id, time, text, done}]
  fps: 24,           // 目前影格率
  dropFrame: false,  // 是否 Drop-frame（29.97 DF）
  duration: 0,       // 片長（秒）
  selectedId: null,  // 主選取字幕 id
  selectedIds: [],   // 多選集合
  activeEdge: 'start',// 上下鍵步進中停在 start 或 end
  pxPerSec: 80,      // 時間軸縮放（每秒像素數）
  viewStart: 0,      // 時間軸左緣對應秒數
  exportIn: null,    // 輸出範圍 In（時間軸秒數，可 Undo/Redo）
  exportOut: null,   // 輸出範圍 Out（時間軸秒數，可 Undo/Redo）
  inPoint: null,     // I 按下但尚未 O 的暫存起點
  subMode: false,    // 上字幕模式（O 後自動跳下一句）
  clips: [],         // 視訊／靜態圖片片段；圖片含 type:'image' 與自身幾何
  videoTracks: [],   // 視訊軌：visible / locked；圖片可獨立放在最上層
  externalAudioState: [], // 可重建的外部／解除音訊 placement（不含 runtime Audio）
  timecodeWatermark: false, // 僅播放器監看的 config 偏好，不寫入專案檔
  ...
}
```

`exportIn/exportOut` 是專案時間軸狀態，不是只有播放器控制元件的暫存值；因此它們進入
`history.js` 快照、`.subtool` 儲存資料與匯出範圍。反之，`timecodeWatermark` 是使用者的
監看偏好，只由 `config.json` 保存；是否把 TC 燒進影片是每一次匯出對話框的選項，兩者不可混用。

圖片幾何也屬於**每個 clip**，不是整條視訊軌的全域屬性：`{type:'image', scale, posX, posY,
in, out, offset, vtrack}`。這個區分讓同一軌的兩張圖片可以有不同大小與位置，並確保
History、Project 與 export filtergraph 使用同一份資料。

**工具函式**：
- `newTrack(name)` — 建立軌道物件
- `setFps(v)` — 設定影格率（同步更新 UI 下拉選單與時碼顯示）
- `snapFps(v)` — 將任意 fps 值對齊到允許集合（23.976/24/25/29.97/30）
- `ensureTrackCount(n)` — 確保至少有 n 條軌道（新專案/init 用）
- `DESK` — Electron `window.subtool` 橋接物件（`null` 表示瀏覽器模式）
- `IS_DESKTOP` — 布林，是否為 Electron 模式

### `formats.js`（字幕格式解析/序列化）

### `media.js`（媒體引擎、外部音訊素材與解除影音）

#### Media 物件

管理影片播放、Web Audio 多軌混音、ffmpeg 整合。

**音軌種類**（`track.kind`）：

| kind | 說明 |
|------|------|
| `native` | 原生影片立體聲 L/R（`_connectStereo()` 分頻） |
| `element` | `<audio>` 元素（外部音檔或抽取聲道） |
| `buffer` | AudioBuffer（ffmpeg.wasm 解碼後存入記憶體） |
| `nativeTrack` | 瀏覽器原生多音軌（少數瀏覽器支援） |

**虛擬播放模式**（`video.src` 為空時）：
- 以 `performance.now()` 計時模擬播放位置
- `_vTime` + `_vStart` 維護當前時間

**seek 精準對齊**：每次 `seek(t)` 都呼叫 `snapTimeToFrame(t, fps, df)` 確保落在整格。

**空專案 seek**：`State.duration === 0` 時允許 `Math.max(0, t)` 而不 clamp 至 0，讓空專案可移動播放點先排字幕。

**靜態圖片**：圖片是 `Seq` 的視覺片段，不交給 `<video>` 或 mpv 解碼／時鐘。`app.js` 在播放
時間落在圖片 clip 的 `offset + (in…out)` 範圍內建立可操作的疊層；一般預覽直接以 DOM 操作，
mpv 原生預覽則透過透明 guide 視窗轉送受限 pointer 事件。新增第一支主影片時，`Media` 會保留
既有 image-only timeline，不能因初始化序列而清掉圖片。

#### Wave 物件

波形峰值資料管理。

| 方法 | 說明 |
|------|------|
| `compute(ab, chIdx)` | 從 AudioBuffer 計算 min/max 峰值桶（100 桶/秒） |
| `computeFromWav(buf)` | 直接從 WAV ArrayBuffer 解析（不需 decodeAudioData，供 Electron 快取讀取） |
| `initLive()` | 長片模式：初始化空白峰值陣列，播放時由 `captureLive()` 逐桶填入 |
| `captureLive()` | 由 `rafLoop` 呼叫，從 AnalyserNode 擷取即時波形 |
| `registerSources(wavePath, channels)` | 記錄多音源（主混音 + 各聲道），驅動波形來源選擇器 |
| `selectSource(idx)` | 切換顯示哪個聲道的波形（延遲解碼，含競爭條件保護） |

### `subio.js`（匯入/匯出，~620 行）

**格式自動辨識** (`detectSubFormat`)：依副檔名優先，次以文字特徵（`[Script Info]` → ASS；`\d+ --> \d+` → SRT；時碼模式 → Encore；其餘 → TXT）。

**匯入流程**：
1. 取得文字（Web: `FileReader`；Desktop: IPC）
2. 若尚未載入影片，彈窗詢問 FPS
3. 解析字幕（含換行符號 `\\`/`//` → `\n` 轉換）
4. 彈窗選擇目標軌道（可新增軌道或附加到現有軌道）
5. `snapTimeToFrame` 對齊影格後寫入 `State.cues`

**匯出流程**：
1. 彈窗選擇格式與軌道（多軌時每軌各一個檔案）
2. 序列化 → `encodeUTF16LE` → 下載（Web）或 IPC 寫檔（Desktop）

**序列影片／WAV 匯出**（桌面版）：`_runExportVideo()` 會把經過輸出 `[In]/[Out]` 裁切後的
`State.clips`、視訊軌、專案音訊路由與可見字幕交給 `ffmpeg:exportVideo`。圖片 clip 必須明確傳
`type:'image'`、`scale`、`posX`、`posY`，主程序才會將來源作為 `image2 -loop 1` 輸入，而不是只
解一格。交付用 TC 只在影片格式可選，起點由 `secToEncore(exportIn, fps, dropFrame)` 計算；它位於
ASS 字幕之上，字型使用更紗黑體的等寬數字字型。WAV 是多聲道 PCM，不支援字幕或 TC。

## 6. Electron 與瀏覽器雙模式差異

### 偵測方式

```js
// state.js
const DESK = window.subtool?.isDesktop ? window.subtool : null;
const IS_DESKTOP = !!DESK;
```

### 核心差異

| 功能 | 瀏覽器版 | Electron 桌面版 |
|------|---------|----------------|
| **開啟影片** | `<input type=file>` / 拖放 → `URL.createObjectURL` | `DESK.openMedia()` 對話框，或**拖放**（`DESK.getFilePath` = `webUtils.getPathForFile` 解析路徑）→ 皆走 `loadDesktopMedia()` |
| **MXF / 大檔支援** | ❌ ffmpeg.wasm 限 1.6 GB | ✅ 系統 ffmpeg，無大小限制 |
| **多音軌** | ffmpeg.wasm 逐一抽取（阻塞） | DESK.ingest() 單次多輸出，並行抽取 |
| **mpv 秒開** | ❌ 不支援 | ✅ 偵測到 mpv.exe 時，非原生格式幾秒內即播放 |
| **波形** | 整檔 decodeAudioData（<500MB）或播放時即時擷取 | 系統 ffmpeg 抽出 8kHz mono WAV 後解析 |
| **匯入字幕** | `FileReader` | `DESK.importSub()` IPC |
| **匯出字幕** | `URL.createObjectURL` 觸發下載 | `DESK.exportSub()` IPC 寫檔至磁碟 |
| **存/讀專案** | 下載檔案 | `DESK.saveProject()` / `loadProject()` IPC |
| **自動備份** | 每 3 分鐘靜默存入 `localStorage` | 每 3 分鐘寫入 `.subtool_AutoSave/` 子目錄 |
| **Video 安全性** | `webSecurity: true`（受 CORS 限制） | `webSecurity: false`（允許 `file://` 媒體） |

## 7. 關鍵流程說明

### 7.1 字幕渲染流程

字幕在兩個地方渲染：**字幕列表**（側欄 DOM）與**影片疊層**（`#videoSub` 絕對定位 div）。

**影片疊層渲染（`renderVideoSub`）**：
1. 取得當前播放時間 `t = Media.displayTime()`
2. 對每個可見軌道，篩選 `c.start <= t <= c.end` 的字幕
3. 依軌道 `posPct`（距底部百分比）計算垂直位置
4. 設定 `#videoSub` div 的 innerHTML（escapeHTML + `\n` → `<br>`）

**mpv 模式字幕渲染（`refreshMpvSubs`）**：
1. 以 `SubFormats.toASS(State.cues, fps, tracks, ...)` 序列化全部字幕
2. base64 編碼後透過 IPC 傳給 Electron 主程序
3. 主程序呼叫 mpv `sub-reload` → 載入暫存 .ass 檔案

防抖 100ms 避免快速連續輸入時頻繁重建。

### 7.1b 圖片與時間碼 overlay 流程

1. `renderVideoSub()` 依 `Seq.isActiveAt(clip, Media.displayTime())` 取得作用中的圖片，建立
   `.img-wrap`、虛線選取框與控制點；拖曳只修改該 clip 的 `scale/posX/posY`。

   `mpv:setImageGuide`；透明 guide 只在圖片命中區接收 pointer，並以 `mpv:imagePointer` 回送座標。
3. 監看 TC 也使用 `Media.displayTime()`：HTML 預覽顯示 DOM overlay，mpv 預覽交給 guide。
   這是監看偏好，不會變成 ASS 字幕，也不會因為開啟監看而影響匯出。
4. 匯出時 `subio.js` 另行傳送 `timecodeWatermark`；主程序把 `drawtext` 接在 ASS 之後，並以
   `font/更紗黑體/sarasa-mono-tc-nerd-regular.ttf` 保持數字等寬。這才是不可逆的交付 burn-in。

## 8. 字幕樣式系統（v4.23 起；`substyle.js`）

### 資料模型：三層合成

```
STYLE_DEFAULTS  （模組常數，全部欄位的預設值）
      ⊕ track[k]        （軌道級：State.tracks[i] 上的同名欄位）
      ⊕ cue.style[k]    （逐句覆蓋：只存差異，限 CUE_STYLE_KEYS）
      ＝ effStyle(cue, track)   ← 三路唯一的輸入
```

- **舊專案零遷移**：缺欄位由 `STYLE_DEFAULTS` 後援；`track.posPct` 自動當 `posY`。
- **undo 零改動**：`history.js` 用 `structuredClone({cues, tracks, …})`，新欄位自動入快照。
- 樣式面板的編輯對象由 `app.js styleTarget()` 決定：**有選取字幕就寫該句的 `cue.style`，
  沒選才寫軌道**（v4.31.0）。面板九個控件全部收斂到單一 `tsSet()`——之前各自
  `State.tracks[i][k]=v`，等於「改樣式一律套全軌」。

### 座標與對齊

- `posX/posY` 存**百分比**（解析度無關、專案可攜），UI 與摘要以**像素**顯示（`posToPx()`）。
- `align/valign` ＝ 多行多句彼此的對齊，**同時**是文字塊貼齊座標的那一側（＝ASS `\an` 語義）。
  `align=center + valign=middle` 時，座標就是文字塊正中心。
- HTML：容器 `left/top` ＋ `translate(-ax%, -ay%)`；ASS：`\pos(x,y)` ＋ Style `Alignment`。
  兩邊的錨點由 `anchorPct()` 共用。
- **旋轉支點是錨點，不是方塊中心**：ASS 的 `\frz` 繞 `\org`（預設＝`\pos`）轉。CSS 的
  `transform-origin` 必須跟著設成錨點，否則只有「左右中＋上下中」時兩者才重合（v4.30 修）。

### ASS 的表達力邊界（哪些能 inline、哪些只能 Style 行）

| 欄位 | 逐句覆蓋怎麼做 |
|------|----------------|
| 字型/字級/顏色/粗斜/字距/框線/陰影/角度 | inline tag（`cueAssTags()`：`\fn \fs \c \b \i \fsp \bord \3c \shad \frz`） |
| 對齊 `align/valign` | inline `{\anN}`（`assAlignN()`） |
| 座標 `posX/posY` | inline `{\pos(x,y)}`（`cueAssPos()`） |
| **背景色塊** `bgBox/bgColor/bgAlpha` | **只有 Style 行有（BorderStyle=3／BackColour），無 inline tag** → 有覆蓋的句子由 `formats.js` 額外生一條 `Cue_<id>` Style（`STYLE_ONLY_KEYS`） |

### 直書（v4.29.3）

- HTML：`writing-mode: vertical-lr`（**第一行在最左**，非 CJK 書籍的右→左傳統）。
- ASS 無 writing-mode → **一列一個 Dialogue**（`verticalAssCols()`）：
  - **y 交給 libass**：`valign` → `\an`（上8/中5/下2），每列各自貼齊同一基準線
    ＝「多列之間上/中/下對齊」的語義，**完全不必估算文字高度**（各列長度不同、ASS 行高
    也不等於字級，硬估必歪）。
  - **x 自己算**：列距 ＝ `fontSize × lineSpacing`，恰為 CSS `line-height:<number>` 在直書時的
    水平步進 → 與預覽同一個數。整塊寬 ＝ 列數 × 列距，再依 `align` 決定哪一側對齊 `posX`。
- 字距／行距語義：直書時 `letterSpacing` ＝ 字間（縱）、`lineSpacing` ＝ 列間（橫）。

### 字型管線（v4.24 起）

```
font/<資料夾名>/<字型檔>          ← 資料夾名＝UI 顯示名（使用者自取）
   ↓ electron/main.js fonts:list
{ name: 資料夾名, file, family: 檔案內部家族名 }   ← fontNamesOf() 解析 sfnt name table
   ↓                              ↓
FontFace(name, ArrayBuffer)    substyle.assFontName(name) → family
（HTML 預覽）                   （ASS Fontname → libass 靠它比對）
```

- **一個資料夾只取一個檔**：`pickRegularFace()` 挑最接近 Regular（`usWeightClass` 離 400 最近、
  非斜體）的那個。多放字重沒有作用，只會讓安裝檔變大。
- CSS `@font-face { src: url('file://') }` 會被 Chromium 擋（"A network error occurred"）→
  必須用 **FontFace API + ArrayBuffer**。
- 主行程的路徑白名單：`fonts:list` 內要 `allowDir()`，renderer 才取得到 `fs:fileURL`。
- 打包：`package.json` 的 `extraResources` 把 `font/` 送進 `resources/font`；`fontsRoot()` 依
  dev（專案根）→ `resources/font` → 安裝目錄 順序尋找。

### 常用樣式庫（presets；v4.33.3 起含內建）

```
BUILTIN_PRESETS  ← 模組常數，唯讀。目前一筆「預設字幕樣式」＝ { ...STYLE_DEFAULTS }
      ＋
_presets         ← 使用者自訂，桌面存 config.json 的 subPresets 鍵、瀏覽器存 localStorage
      ＝ getAllPresets()   ← UI 列表／名稱比對用（內建永遠在最前）
```

- **內建務必寫成 `{ ...STYLE_DEFAULTS }`，不要另抄一份數值**——抄一份就等於兩個真相來源，
  改了預設值而忘了改內建（或反之）就會漂掉。使用者要求的規格與現行預設值本來就一致。
- `getPresets()` **只回使用者清單**，`savePresets()` 也**只寫使用者清單**並先
  `filter(!isBuiltinPresetName)` —— 否則使用者存一筆同名的就把內建蓋掉，「回出廠設定」失效。
- UI 列表用 `getAllPresets()` 的索引 `i`，但改名／刪除／編輯按鈕帶的是**使用者清單索引**
  `i - BUILTIN_PRESETS.length`（要跟 `getPresets()` 對得上）。新增內建筆數時這裡自動跟著調整，
  但**任何直接拿列表索引去 splice 使用者清單的新程式碼都會錯位**。

#### 編輯常用樣式（v4.34.0；`app.js _presetEdit`）

「編輯」不另做一份樣式編輯 UI，而是**暫借目前軌道當草稿**：把該 preset 套到目前軌，使用者
就用原本那套面板控制項邊調邊看即時預覽（三路照常運作）。

```
_presetEdit = { name, ui, before, trackIdx, targets:{tracks[],cues[]}, old }
                              ↑ 進入前的軌道樣式      ↑ 進入前就符合舊樣式的軌與句
```

- 進入編輯時**先掃出 `targets`**——套上草稿之後就分不出誰原本符合了。
- **編輯期間 `styleTarget()` 強制回整軌**（`if(_presetEdit) return {cues:[]}`），否則使用者
  剛好選著一句時，改動會跑進 `cue.style` 逐句覆蓋、按完成時從軌道抓不到草稿。
- 完成：寫回 preset ＋ 把 `targets` 全部換成新樣式；**目前這軌若不在 `targets` 內就還原**
  ——它只是借來當畫布，不該被順手改掉。取消：只還原 `before`。
- 「誰套用了這組樣式」用**全欄位相符**判定，與 `subtitles.js _trackPresetName` 同一套判準。
  **資料模型裡沒有「這條字幕套用了哪個 preset」的欄位**，只能靠比對；要改成存名稱的話，
  這兩處必須一起改。

### 樣式面板版面（`index.html #trackStyle`）

欄位順序由使用者指定，改動前先確認需求（歷經 v4.34.0～v4.34.4 多次微調）：

```
行1  大小 60/80＋數值 ｜ B I ｜ 對齊 [上下▼][左右▼] ｜ 直 ｜ 字色＋三色鈕 ｜ 字型▼
行2  座標 X Y ｜ 角度 ｜ 字距 行距 ｜ 框線＋框色 陰影 ｜ 底＋底色＋不透明度
行3  常用樣式 [套用▼] ☆存為常用 ⚙管理 ｜ ⇩全軌統一
```

- 字型下拉**只列 `font/` 掃出來的**（v4.34.4 拿掉「自訂…」；手打系統字型名匯出時常配不到，
  見 §0.3）。但**保留「字型不在清單時動態補一個 option」**——舊專案存過已移除／改名的字型

## 9. WebCodecs 預覽引擎（v4.20 起；`decode/player.js`）

自寫播放器，取代「原生 `<video>` 只能顯示單軌」的限制，做到**多軌即時合成預覽**
（疊層／透明度／子母畫面／淡入淡出／真溶接），且**與匯出一致**。

```
每個來源檔一個 SourceStream
  demux（索引，見 §10）→ VideoDecoder → frames[] 淺佇列 → 取最接近 t 的 frame
rafLoop 每幀 tick()：
  Seq.clipsAt(t) 由下而上 → 逐層取 frame → Canvas2D 合成 → #previewCanvas
```

要點與踩過的坑：

- **`<video>` 仍負責聲音與時鐘**（`media.js` 完全不動）；canvas 不透明蓋在它上面。
- **畫布 ＝ 專案輸出解析度**（`State.videoWidth/Height`），與匯出同一張畫布 → 字幕大小不隨各片
  解析度／比例改變。曾用「第一層的解析度」當基準 → 疊加不同片時字幕大小不同。
- **預設軟解**（`hardwareAcceleration: 'prefer-software'`）：部分環境硬解連續解碼會卡死
  （約第 18 幀）；720p 軟解 >3000fps，夠用。
- **跳轉偵測要比對 keyframe 索引，不能比距離**：長 GOP 從頭重解時，用「目標 vs 已餵位置」的
  距離會每幀誤判成再次跳轉 → 無限 reseek、永遠吐不出 frame。
- **B-frame 的首幀 cts 常 >0**：`SourceStream.startUs` 要夾住下界，否則 `t=0` 被誤判成後退。
- **沒有任何可解圖層時要 `_hideCanvas()`**：不透明畫布留著會蓋成全黑（曾出現「看得到字幕、
  看不到影像」）。
- 只有 `!layers.length` 才讓回 mpv；頂層暫時解不出來時**保留上一幀**，否則 HTML 字幕層會被
  一起藏掉（曾出現「疊加後字幕消失」）。

### 為什麼【不】做 WebGL 合成（原 #26，已結案不做）

曾規劃「階段4：改用 WebGL 合成」當作效能優化。**實測後結論是不值得做**：

| 情境（3 軌重疊、含 scale 0.5＋opacity 0.7） | tick 平均 | 繪圖（fillRect＋drawImage） |
|---|---|---|
| 畫布 974×592（一般視窗） | 0.353 ms | **0.302 ms/幀** |
| 畫布 2894×1743（**8.7 倍面積**） | 0.380 ms | **0.315 ms/幀（+4%）** |

- 合成只佔 60fps 預算（16.7ms）的 **約 2%**。
- **面積放大 8.7 倍，成本只增加 4%** → 瓶頸不是填像素，而是每次呼叫的固定開銷。
  也就是說 **Canvas2D 早已在 GPU 上合成**，WebGL 沒有東西可優化（它自己還要付每幀貼圖上傳）。
- 代價卻是：多一條渲染路徑要維護、context lost 處理、驅動相容性問題。

> 量測方式：包住 `previewCanvas` 的 2D context 與 `WCPreview.tick`，靜止在三層重疊區內統計
> 543 幀（rafLoop 不論播放與否每幀都會完整合成）。
> **注意兩個會讓量測失效的坑**：①片段只有 2~3 秒，一播就播完 → 後半段全是黑幀、數字被稀釋；
> ②三段若各自接續而非重疊，`clipsAt(t)` 只會拿到一段 → `mode` 是 `black`＝根本沒量到合成。
> 量測前後都必須斷言 `mode==='wc'`，並檢查「繪圖呼叫數 ÷ 幀數 ＝ 1＋層數」。

## 10. 串流式 demux（v4.29 起；`decode/demux.js`）

長片的 720p proxy 實測 **2.6–4.25 Mbps**（CRF26 ＋ 每 0.5s 一個關鍵幀），**兩小時＝2.3–3.7GB**
——整檔讀進記憶體不可能。

```
demuxIndex(url)
  ├─ rangeWorks()：先用 1KB 探針確認此來源支援 Range
  ├─ 取檔頭（4MB → 24MB 兩級）餵 mp4box → onReady → buildSampleLists()
  │    每顆樣本的 offset/size/cts/is_sync 全在 moov（stco/stsz/stts/ctts/stss），不需要 mdat
  └─ 回 { config, index[], keyIdx[], maxEnd }        索引 10 萬顆樣本僅約數 MB

SampleReader：對齊格線的「樣本視窗」按需抓位元組（上限 48 顆或 4MB，常駐 4 個視窗）
退路：moov 不在檔頭（非 +faststart 的外來檔）→ 明確失敗 → player 靜靜退回整檔路（1.5GB 上限）
```

**Range 的坑（重要）**：Chromium 的 `file://` loader **會套用 Range，但回 200 且不給
`Content-Range`**；而真正忽略 Range 的實作會回**整個檔案**——兩者狀態碼相同，**只有長度能分辨**。
所以 `fetchRange()` 一律用長度把關，長度不符即報錯，**絕不把「整檔」當「某一段」餵進 decoder**
（那會解出花屏，而且錯得很安靜）。

實測（1.66GB／67 分鐘／100,500 幀）：索引 39ms、常駐位元組 2.5MB、JS heap 30MB。

## 11. 驗證方式（CDP 真機）

單元測試（`npm test`，vitest）只涵蓋純函式。**所有 UI／媒體／字型／匯出的行為一律真機驗證**：

```bash
# 用【獨立的 user-data-dir】啟動 dev electron，切勿殺掉使用者安裝的 SUB Tool.exe
electron . --remote-debugging-port=9223 --user-data-dir=<temp> \
  --disable-background-timer-throttling --disable-renderer-backgrounding \
  --disable-backgrounding-occluded-windows
```

- `window.SUB` 是除錯把手（`app.js` 尾端），暴露 State/Media/render*/toASSFromState/_stageRect/
  WC/SubStyle 等。
- 互動要發**真事件**（CDP `Input.dispatchMouseEvent`）——`Runtime.evaluate` 造假事件驗不到
  pointer capture／pointer-events／hit-test。
- **背景視窗的 setTimeout/rAF 會被節流** → 一定要加上面那三個 flag，並 `Page.bringToFront()`。
- **測試必須自己處理擋路的對話框**：`openCueEditModal` 會先 `await ensureProjectSaved()`，
  全新實例下會跳「開始前先儲存專案」把後續視窗擋住。不處理的話，「前一輪剛好把專案標記成
  已存檔就過、換個乾淨實例就掛」——這種看時機決定過不過的測試比沒測還危險。
- **每支測試用全新實例跑**：共用同一個 app 實例時，前一支留下的選取狀態會污染後一支。

判準請見 §0.6「有產出不等於對」。
