# ADR-0003：倒帶以實際呈現畫格節流

## 狀態

已接受。決策日期：2026-08-27。

## 背景

固定計時器若持續累積倒帶 seek，解碼落後就會形成舊目標佇列：時間軸先走，畫面仍在處理過時畫格。原生 mpv 反向播放也可能先正常、再因長 GOP 停住，單次啟動檢查不足以保證持續流暢。

## 決策

同一時間最多執行一個呈現請求，等待期間只保留最新目標。時間軸呈現位置須由目前可見的 presenter 提供實際畫格證據，舊目標可以被捨棄。

HTML video 以畫格 callback 回報；mpv 播放定位核對目標 `time-pos` 與同一請求的 `playback-restart`，暫停定位則核對 command ack 及命中的 `time-pos`。同格定位沒有新事件時，host 在命令確認後主動查詢位置。WebCodecs 須完成全部可見層的繪製。

符合資格的單一 mpv 片段可優先使用原生反向播放，但整段持續觀察呈現位置；停止下降即改走時間軸 fallback。fallback 依經過時間、精確專案 FPS 及倍率產生最新目標。持續倒帶靜音，單次方向鍵逐格保留短促 scrub 音訊。

背景 ingest 準備 720p 短 GOP Proxy，減少母素材 GOP 對倒帶的限制；多數編碼器使用 GOP 1，NVIDIA NVENC 因編碼器限制使用 GOP 2。倒帶可在相同來源時間切入 Proxy，停止後回到母素材；Proxy 的用途限於預覽。

一般長距離跳轉也共用呈現 session。使用者在等待畫格期間更新的 play／pause 意圖，以最新一次為準；畫格尚未抵達時，presenter 時鐘、序列推進及音訊 follower 維持停止。

## 後果

解碼跟不上時會跳過中間畫格，以控制延遲及維持影音一致；連續倒帶不承諾逐張顯示每個影格。倒帶 session 與 presentation core 分別持有倒帶節流及呈現請求生命週期，控制器不另維護 seek 佇列、epoch、watchdog 或固定 30 FPS 計時。

新增 presenter 必須提供能與請求配對的實際呈現訊號。一般 seek 及背景音訊接管共用播放意圖，避免舊 pause、遲到解碼或音訊起播覆蓋較新操作。

原生可播的 H.264／H.265 MP4 也會準備背景 Proxy，增加快取空間以換取持續倒帶的 cadence；正播、快轉及交付仍使用母素材。

目前時間權威與呈現契約見[FPS／時碼一致性](../FPS_時碼一致性.md#3-呈現生命週期)，原生證據與 IPC 細節見[Electron 維護手冊](../Electron_維護手冊.md)。
