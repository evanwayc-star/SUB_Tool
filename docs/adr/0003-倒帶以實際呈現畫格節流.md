# ADR-0003：倒帶以實際呈現畫格節流

## 狀態

已接受（2026-08-27）

## 背景

連續倒帶若按固定計時器累積 seek，解碼速度跟不上時會形成舊目標佇列。播放點可先跑到新位置，
畫面卻仍在處理舊畫格，造成卡頓與影音不同步。mpv 原生反向播放也可能先正常倒退，之後才因
長 GOP 素材停住，因此只在開始時檢查一次不足以保證持續可用。

## 決策

倒帶只允許一個呈現請求正在執行，等待期間只保留最新播放目標；較舊的中間目標可丟棄。
時間軸位置必須等目前可見的 presenter 回報實際畫格後才提交：HTML video 使用畫格回呼，
mpv 使用每畫格 `time-pos` 與播放重新開始事件，WebCodecs 使用所有可見圖層完成繪製的時間戳。

符合資格的單一 mpv 片段優先使用原生反向播放，但整段倒帶期間持續監看呈現位置；若不再下降，
自動切換成時間軸 fallback。fallback 依經過時間、專案精確 FPS 與目前倍率產生最新目標。
所有持續倒帶都靜音；單次方向鍵逐格仍保留短促 scrub 音訊。

mpv 倒播不直接依賴母素材 GOP：背景 ingest 產生每 0.5 秒一個 keyframe 的 720p preview Proxy；
Proxy 就緒後，倒帶在相同來源時間切入短 GOP Proxy，停止時再切回母素材。Proxy 永遠只屬預覽，
不得進入匯出。

## 後果

解碼落後時會跳過中間畫格，以控制延遲和影音一致性為優先，不保證逐格播放每一張畫面。
控制器不再擁有 seek 佇列、epoch、watchdog 或固定 30fps 計時；這些責任分別收斂到倒帶 session
與 media presentation core。新增 presenter 時必須提供可對應到同一請求的實際呈現完成訊號。
原生可播的 H.264／H.265 MP4 也會在背景多產一支 Proxy，換取持續倒帶的穩定 cadence 與較高的
cache 儲存用量；正播、快轉與匯出仍使用母素材。
