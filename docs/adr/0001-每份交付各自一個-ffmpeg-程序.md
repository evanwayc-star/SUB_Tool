# ADR-0001：每份交付各自一個 ffmpeg 程序

## 狀態

已接受並實作。決策日期：2026-07-25。

## 背景

匯出佇列必須處理同一專案的多份格式與解析度。典型來源包含約 44 GB MXF 與 186 GB ProRes，重複讀取的成本很高；ffmpeg 的單次讀取、多路輸出曾在匯入實測中證明可行，因此是當時認真考慮的選項。

交付同時有四項互動要求：每份各自暫停／繼續／停止、執行期間可追加工作、單份失敗不拖累其他份，以及逐份進度與預估完成時間。

## 決策

每份交付使用獨立的 ffmpeg 執行流程。佇列預設並行度為 1，使用者可調整並行度；工作完成後的封裝或光碟製作仍屬於該份交付。

## 理由

單一 ffmpeg 多輸出的輸入、濾鏡分支及目的地在啟動時已固定，無法自然提供上述四項互動。暫停或終止會影響整個程序；追加交付需要另啟程序；程序失敗會波及所有輸出；共用進度也不足以代表各份的完成情況。

預設只執行一份，是為了控制解碼器、硬體編碼及記憶體壓力。既有主程序註解曾記錄同一實體來源重複開啟 input，建立過多 hwaccel 實例而耗盡 VRAM 的事故。大型 MXF 的多份 NVENC 並行可能拖慢總體處理及預覽，因此並行度保留為可調設定。

## 代價

N 份交付會重複讀取、合成及燒錄字幕，整批的讀取量與計算量高於單次多路輸出。這項成本換取每份的操作與失敗隔離，並讓第一份完成時間不必等待其他輸出。

## 未來若總批次時間真的痛

當實測證明重複合成已成主要瓶頸，可以評估先產生共用的無損／ProRes 中間母帶，再由各份獨立轉碼。評估時仍須保留逐份停止、追加及失敗隔離；不能只因總耗時而回到共用一個 ffmpeg 多輸出程序。
