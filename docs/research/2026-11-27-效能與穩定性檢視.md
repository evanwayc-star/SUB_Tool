# SUB Tool 改善清單

2026-11-27 檢視 Windows 工作區 `1cd0475`。優先處理會改變交付內容、令使用者無法完成工作，或使復原失效的問題。其次才比較編碼速度、等待時間與工作區效率。編號供排程引用。

## 本次實作與驗收

下表對應原始清單的編號。後文的問題描述、舊版耗時與程式行號保留作為改善前基準。

| 編號 | 實作與驗收結果 |
|---|---|
| 01、03、15 | ProRes 422 HQ 的合成鏈保留 10-bit 4:2:2。讀回細色線與 10-bit 階梯，涵蓋透明圖、ASS 與淡化。八聲道長 WAV 寫入 RF64，實測 4,296,960,000 bytes PCM 的表頭、聲道與首尾取樣。一般影片及音訊在原子替換目的檔前會檢查容器、音流與片長。 |

在 8 秒串流樣本中，暫時 MIX 的實際 RMS 約 0.12，按下靜音後為 0。暫時 MIX 適用於各來源聲道增益相同的情況。若單獨靜音某一聲道或使用不同增益，會等獨立聲道就緒後依照原配線播放。Windows 的單一命令列和同時開啟的管線仍有系統上限。1,000 個剪段已實際輸出；若同時指定 1,000 條相異長路徑而超出上限，程式會提示分批並保留舊成品。

Windows 完整驗證依序執行 `npm run lint`、`npm test`、`npm run build`。459 個測試檔通過，共 8,330 項通過、3 項跳過。建置後在 1024 至 1920 像素寬的 Electron 視窗確認控制項可操作。另以獨立設定檔啟動本機 x64 測試包，確認主畫面與 F10 工具列載入，封裝內的 FFmpeg 和 ffprobe 可用，且成功選到 NVENC。由封裝內的匯出程序產生一秒 440 Hz WAV，解碼讀回 48,000 個取樣、440 次正向過零與 0.0884 RMS。macOS、實體 NAS 和外部剪輯／音訊軟體的相容性仍待各環境驗收，付費語音辨識服務以模擬回應驗證重試行為。

## 單人編輯穩定性複測

以下使用 Windows 本機的隔離設定檔與測試素材。時間從各列列出的操作開始量測。字幕物件數直接計算歷史快照保留的不同物件，不是程序記憶體用量。

| 情境 | 修正與讀回結果 |
|---|---|
| WebCodecs 連續定位後按播放 | 用紅、綠、藍 H.264 影片依序跳至 3.4、6.4 秒。原先舊定位會等滿 10 秒才讓出播放器。修正後底層定位完成即讓最新請求等候自己的合成畫格，兩次實際起播由 10,007／10,005 ms 降至 56／25 ms。讀回畫布中央藍色像素與 6.400 秒來源時間，並確認其後畫格持續前進。 |
| 大量多選後開始拖曳 | 兩份建置只替換時間軸相關的兩個模組。10,000 句中從搜尋結果選取分散的 2,500 句，改為按軌道排序、一次計算整組的鄰句邊界。按下滑鼠的五次中位數由 347.5 降至 20.8 ms。滑動為 13.5／13.7 ms，放開為 25.7／26.8 ms。實際讀回所有選取句移動 5 格、其餘字幕原位，並驗證預覽移動 20 px、鄰句阻擋、復原與重做。[驗收腳本](../../scripts/acceptance/verify-timeline-group-drag.js) |
| 修改帶逐字時間的字幕 | 3,000 句、每句 8 詞，連續修改中間同一句 12 次。復原步驟共用內容相同的歷史字幕，仍會偵測逐字資料的原地修改。兩份封裝各做三輪、各量 36 次，建立復原紀錄的中位數由 14.6 降至 2.6 ms。相同 13 個步驟保留的字幕物件由 39,000 減至 3,012。驗證 Undo、Redo，並從輸出的專案逐筆比對全部文字與 24,000 個詞的起訖。 |
| 自動備份檢查與拖曳期間存檔 | 同一份 3,000 句專案，透過頁面離開事件觸發備份回呼，21 次乾淨專案檢查的中位數由 21.8 降至 12.6 ms。另以 300 句樣本修改一句，從本機草稿讀回新台詞及逐字資料。10,000 句中拖曳 2,500 句時，建立已提交內容快照的五次中位數由 53.6 降至 7.2 ms，逐一核對 10,000 句均保留拖曳前的起訖。 |
| Proxy 完成時同時存檔 | 在本機用正式桌面存檔處理器儲存 1,000 句，並回收 180 份已完成的續編收據。分段回收改為非同步讀取，每份回收前核對檔案身分。新舊各跑五輪，排定到存妥的中位數由 115.0 降至 17.9 ms，逐輪讀回最後一句。收據全部清完由 106.6 增至 139.6 ms。 |

桌面整合另以 120 秒、1280×720、25 fps 的 H.264＋AAC 母片啟動原生 Proxy。進度 11% 時編輯字幕，正常存檔耗時 17.8 ms，全程與轉檔重疊。存妥後 4.38 秒 Proxy 完成。從磁碟讀回台詞、第 1 軌、起訖 2.24–4.80 秒及母片路徑。再解碼完整 3,000 格，在 1、61、119.92 秒用同一 BT.709 矩陣核對母片與 Proxy 的取樣像素。

用 Windows x64 測試包及 54 秒、25 fps 的 H.264＋AAC 素材驗收原生 mpv。實際呈現速率分別為正播 0.986×、快轉 2.005×／3.956×、倒帶 −0.989×／−3.974×。左右方向鍵各六次，以及快速交錯方向的 12 組操作均命中目標格，快速操作最後一次請求最久 9.2 ms 顯示。[播放驗收腳本](../../scripts/acceptance/verify-transport-smoothness.js)

最終工作樹依序通過 lint、完整測試及 build。461 個測試檔共 8,388 項通過、3 項跳過。另核對 Windows x64 測試包的單檔介面、桌面主程式與 Proxy 處理程式內容均與此次建置一致。

## 排程與量測

1. **先保交付和復原。** 第 01–05 項各自有可重現輸入。WAV 與 Windows 命令長度已有小幅改動即可成立的對照；ProRes 應獨立驗完整合成鏈。三者可平行處理。
2. **再改善天天遇到的互動。** 第 06、07、16、17、18 項分別縮短開片、減少打字停頓、增加可見字幕及補齊鍵盤入口。若主要使用 macOS 或無 mpv 環境，將第 08、11 項一起提前。
3. **長片運算用實際工作負載決策。** 固定同一素材、匯出規格和硬體，分別量冷／熱快取、本機 SSD／實體 NAS、單件／三件交付。記錄首個可聽畫格、可跳尾時間、搜尋輸入至繪製 P95、FFmpeg 啟動前耗時、總轉檔時間、峰值 RAM／VRAM 和磁碟讀寫量。沿用既有逐格與倒帶量測，新增首聲、搜尋與長案指標。[播放量測](https://github.com/evanwayc-star/SUB_Tool/blob/1cd0475af50c7d4e8bb8dc23f572402d76c31e23/scripts/acceptance/verify-transport-smoothness.js#L682)
4. **保留已驗證的設計。** 交付使用母素材；每份工作獨立取消；來源波形已有 checkpoint；硬體 Proxy 有失敗退路。短 GOP、無 B 格、最高 720p 的 Proxy 已存在。若多份相同燒字幕工作占大宗，再比較一次產共用中間母帶與逐份重算的總耗時、空間和逐件取消能力。[Proxy 規格](../../shared/preview-proxy.cjs) · [交付並行的設計決策](../adr/0001-每份交付各自一個-ffmpeg-程序.md) · [架構與驗收原則](../技術架構說明.md)
