# 語音辨識引擎改善評估

初次研究於 2026-08-25。供應商能力與時程以 **2026-10-21** 的官方文件查核為準。2026-11-03 僅核對本機程式、套件及時間碼退路，未重查服務或重跑品質評測。比較範圍為 OpenAI、Groq、Gemini、本機 Whisper，Azure Speech 與 ElevenLabs 未列入。[操作](../使用說明.md#8-語音辨識與文本匹配) · [版本歷史](../版本變更紀錄.md)

## 1. 量測什麼

| 面向 | 指標 |
|---|---|
| 文字 | 繁中 CER、英文 WER、專名、重複、幻覺文字。 |
| 時間 | 起訖絕對誤差、倒退、負時長、重疊、跨越長靜音。區分逐字、逐段與提示詞估計的時間證據。 |
| 斷句 | 語意邊界、顯示時長、閱讀速度、需人工修整比例。 |

## 2. 四條辨識路徑

| 路徑 | 專案採用與已知限制 | 主要來源 |
|---|---|---|
| OpenAI | `whisper-1` 請求 `verbose_json`、word＋segment。研究時的官方公告列 2027-02-26 關停，為遷移規劃依據。`gpt-transcribe` 的 prompt、keywords、languages 提供文字上下文。其中 `languages` 與舊模型 `language` 契約不同。專案尚未提供該文字優先選項。 | [轉寫指南](https://developers.openai.com/api/docs/guides/speech-to-text) · [Create transcription](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create) |
| Groq | `whisper-large-v3` 提供 word、segment 與段落品質 metadata。專案保留逐字證據並做長片分段去重。以實際送出的 PCM／WAV 查聲道選擇。 | [Speech to Text](https://console.groq.com/docs/speech-to-text) |
| Gemini | 用音訊提示轉寫並指定 JSON MIME。模型需同時符合音訊能力清單及帳號 Models API 資格。提示生成的段落時間只視為估計，response schema 仍待實作。 | [音訊理解](https://ai.google.dev/gemini-api/docs/audio) · [Structured outputs](https://ai.google.dev/gemini-api/docs/structured-output) |
| 本機 Whisper | Tiny／Base／Small／Large v3 Turbo 採 timestamped 模型，以 29 秒 chunk、5 秒 stride 推定逐字時間。Large v3 使用句級，不支援逐字 cross-attention 時也退回句級。WebGPU 失敗可用 WASM。須實測缺字、零時長及跨段重複。 | [Transformers.js 3.3.3](https://github.com/huggingface/transformers.js/blob/3.3.3/src/pipelines.js) · [timestamped 模型卡](https://huggingface.co/onnx-community/whisper-small_timestamped) |

### Gemini 模型准入與時間驗證

- **2026-10-19** 查到專案仍優先 2.5／2.0 並保留 1.5 候選。當時官方音訊範例已用 `gemini-3.8-flash`，停用表列出 2.0 Flash 於 2026-06-01 關停。[音訊範例](https://ai.google.dev/gemini-api/docs/audio) · [停用表](https://ai.google.dev/gemini-api/docs/deprecations)
- **2026-10-21** 改為遍歷帳號模型分頁，優先 2.5 Flash。候選須列出 `generateContent`，且 adapter 清單已核對該型號支援音訊輸入及結構化文字輸出。只有「模型不存在」或明確不支援音訊才換合格候選。權限、金鑰、流量及一般請求錯誤原樣回報。[Models API](https://ai.google.dev/api/models) · [2.5 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash)
- 驗收涵蓋時間缺值。過去會為缺值補造時間。現僅採有限、非負、終點大於起點的資料，接受合法零與數字字串。混合結果略過壞段，全無有效時間則失敗。受控回傳走過 provider、session、commit，確認沒有產生虛假定時字幕。未用雲端金鑰實測。

## 3. 已實作的共用處理

| 責任 | 行為 |
|---|---|
| [來源與雲端](../../src/speech-recognition-engine.js) | 依指定母素材聲道或全來源混音，產生 16 kHz mono。「最後兩軌」按實際來源座標選取。監聽、bus、交付配線獨立。OpenAI／Groq 最多每段 600 秒、重疊 10 秒，依跨段逐字證據去重。桌面可暫壓 MP3，網頁或壓縮失敗時送 WAV。OpenCC 僅統一字形。 |
| [本機 worker](../../src/speech-recognition-worker-runtime.js) | 管本機分段與生成參數。 |
| [逐行稿對齊](../../src/transcript-alignment.js) | 優先用 words，保留每個非空原稿行的文字與行界。雙側錨點可靠時才可有限插值，須標記待校對。缺乏可靠時間則保留未定時佔位。 |
| [工作生命週期](../../src/speech-recognition-session.js) | 管工作所有權、取消、結果審閱與提交。[領域詞彙](../../CONTEXT.md) |

## 4. 尚待驗證的改善

| 優先 | 提案 | 驗收 |
|---|---|---|
| P0 | Gemini response schema、來源範圍與單調性檢查 | schema 約束結構，另測越界時間、順序與實際邊界誤差。 |
| P0 | 供應商共用逐字斷句與時間證據格式 | 候選欄位 `text`、`words`、`segments`、`timingEvidence`、`providerMetadata`。保留逐字／段落／估計的差異，尚非所有 adapter 的契約。 |
| P1 | OpenAI 文字優先模式、可選第二輪時間對齊 | 同素材比對兩輪文字差異、時間、成本及延遲。預設維持單次請求。 |
| P1 | 本機英文模型、近似時間品質標記 | 量測邊界、下載、記憶體與推論時間。 |
| P1 | 以段落 metadata 提醒人工複核 | 用固定繁中／英文樣本校準閾值。 |

## 5. 重測條件

固定樣本需涵蓋繁中、英文、多人、快語速、背景配樂、專名、長靜音與長片。除上表品質指標，需記錄無效時間數、人工修整比例、推論時間、峰值記憶體、下載量、雲端成本。逐行稿再比對行數與原文。API、模型、套件或音訊前處理變動後，重查主要來源及帳號可用型號，再跑同一批樣本。本次研究未建立跨供應商品質排名。
