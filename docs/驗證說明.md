# 大型影音 / 混音器 — 桌面版驗證說明（v4.6.3）

> 本文是**需要真實大檔、只能人工判讀**的那部分驗證清單（媒體管線、混音、FPS 一致性）。
>
> **一般功能改動請用 CDP 自動驗證**，方法、`window.SUB` 除錯把手、以及兩個「驗證方法本身
> 出錯」的真實案例都寫在 [`開發說明.md`](開發說明.md)；判準見
> [`技術架構說明.md`](技術架構說明.md) §0.6「有產出不等於對」與 §0.7「有沒有顯示只能看
> computed style」。

驗證「mpv 秒開 / 單次讀取轉檔 + 逐聲道音訊 + 混音器電平表 + GPU 編碼 + 快取秒開」這批功能，請用桌面（Electron）版搭配真實大檔測試。

> **開檔有兩條路徑**：
> - 若系統偵測到 **mpv**：非原生格式或多音軌會以 mpv **秒開**（嵌入式覆蓋視窗播放），音軌於背景抽取；狀態列出現「啟動 mpv（秒開）…」。
> - 若無 mpv：走 **ffmpeg 單次讀取轉檔**（有進度 %），完成後以原生 `<video>` 播放。
> 兩種路徑的字幕編輯與混音器行為一致。

## 啟動方式

**驗證用（看得到錯誤，建議）** — 開兩個終端機：

```bash
# 終端機 1：vite dev server
npm run dev
# 終端機 2：Electron 連 dev server（會自動開 DevTools）
npm run electron:dev
```

**一般使用** — 直接雙擊 `啟動桌面版.bat`（build 後開 prod 版，無 DevTools）。

## 驗證清單

### 1. MXF（MPEG-2 4:2:2 + 8 單聲道）

- 開檔後狀態列依序：`讀取媒體資訊…` →「**讀取並轉檔中（單次讀取，大檔需數分鐘）…**」+ 進度 % → `媒體已載入（桌面模式）`
- [ ] 影片畫面出得來（修正前因 4:2:2 是黑的 / 不能播）
- [ ] 🔊 音軌面板出現正確聲道數量
- [ ] 整個來源檔只被讀取「一遍」（不再是 proxy + 每軌 + 波形分開讀很多遍）

### 2. MOV（ProRes HQ 4:2:2 10-bit + 5.1）

- [ ] 影片能播
- [ ] 🔊 出現 6 條聲道（5.1 被 channelsplit 拆成獨立聲道）

### 3. 混音器 🎚（時間軸工具列按鈕）

- [ ] 出現 N 條垂直電平表 + S（獨奏）/ M（靜音）
- [ ] 播放時：有內容的聲道表會跳動、無訊號的保持平的 → 逐聲道聽 + 看，決定要開哪些
- [ ] 表頭取「源頭訊號」：某聲道沒開（靜音）時，表仍會顯示它有沒有內容

### 3.5 專案音訊路由、解除影音與純音訊時間軸

- [ ] 匯入 8 聲道素材後，專案預設至少有 8 條輸出 bus；再匯入 10 聲道素材後，專案可擴至 10 條且既有路由不改變。
- [ ] 將輸出配置設為 `5.1 + Stereo` 時，bus 1–6 與 7–8 的來源範圍、混音器與匯出摘要一致；改成全部 Mono 時，每條 bus 仍獨立。
- [ ] 對兩支不同影音素材分別指定來源→bus 對應，確認調整其中一支不會改到另一支。
- [ ] 對 MXF／MOV 影片執行「解除影音」：完成後有獨立音訊片段；移動、修剪與 `Ctrl+K` 切割音訊都不會移動或切割影片，反向操作也同理。
- [ ] 點左側或素材片段的 `🔊`，按鈕改為 `🔇` 且播放靜音；再點一次恢復。外部音檔與影片原音都要測。
- [ ] 刪除最後一支影片後，外部／已解除的音訊仍能在黑畫面時間軸中播放；WAV 匯出仍可選取。

### 4. 快取秒開

- [ ] 關掉該檔、再開同一支 → 狀態列出現「**使用既有快取，秒開…**」（或「**啟動 mpv（秒開）…**」）且幾乎瞬間載入
- 快取位置（讀取時依序找第一個有效的、寫入時找第一個可寫的）：
  ① 影片同資料夾的 `.subtool_Cache` ② `%APPDATA%\sub-tool\mediacache`（本機中央快取）
- 清除：時間軸工具列的 **🗂 快取管理** 對話框可「清理孤兒檔 / 全部清除」；或直接刪上述資料夾。
  （key = 路徑 + 大小 + 前 1MB 雜湊；來源檔內容變了會自動重轉）

### 5. 確認用到 GPU 編碼

- DevTools console 執行：`await window.subtool.status()`
- [ ] 回傳含 `venc: "h264_nvenc"`（或 qsv / amf；否則為 `libx264`）

### 6. FPS / 時碼一致性（播放器時碼 = 時間軸播放點）

> 背景與設計原則見 [`FPS_時碼一致性.md`](FPS_時碼一致性.md)；程式關鍵點以 `FPS-SYNC` 標記。建議用 **29.97fps NDF** 的長片（一小時以上）測，最容易暴露問題。

- [ ] **同格**：seek 到任一字幕起點並暫停 → 播放器大時碼 與 時間軸播放點正下方刻度的時碼**完全相同**（不差一格）。
- [ ] **逐格精度**：在高時碼處（如 01:20:00 之後）按 `→` 一次只前進**一格**、按 `←` 一次只後退**一格**（不可跳兩格、不可按左鍵又彈回原位）。
- [ ] **刻度一致**：時間軸放大到顯示「格」層級時，播放點所在刻度標籤 與 播放器時碼一致；字幕列表的 In/Out 時碼也與之同格。
- [ ] **mpv 沉降**：以 mpv 路徑開檔，seek 後暫停，反覆數次 → 播放器時碼不會偶爾比播放點多/少一格。
- [ ] **（正常現象，非 bug）** 29.97 **NDF** 在長時碼處，播放器時碼會比真實經過秒數**慢幾秒**（每小時約 3.6 秒）——這是非 drop-frame 時碼的標準特性；若需時碼≈牆鐘，請改用 **29.97 (DF)**。

### 7. 空白專案基本流程

- [ ] 新專案啟動後，時間軸已有「軌道 1」（不需手動新增）
- [ ] 無影片時可拖曳播放點（播放點不卡在 0）
- [ ] 按 `I`/`O` 可在目前位置新增空白字幕並出現在時間軸
- [ ] 第一次匯入影片或字幕時，時間軸自動縮放至完整影片長度

### 8. 專案載入（桌面版特有）

- [ ] 雙擊 `.subtool` 檔案：軟體可自動啟動並載入該專案（包含影片與字幕進度）。

### 9. 圖片素材、監看 TC 與交付 TC（v4.6.1）

- [ ] 在已有影片的專案匯入 PNG/JPG：圖片會成為最上層、預設 10 秒的時間軸片段；播放頭位於它的整段期間內時皆可看見，不能只在第一格出現。
- [ ] 選取圖片後，虛線框與黃色控制點會跟著圖片本身；拖曳圖片可移動、拖曳角點可調整大小。鎖定視訊軌時操作應被阻擋，解鎖後立即恢復。
- [ ] 用 mpv 路徑（例如 MXF）重做上一項：圖片外區域仍可操作字幕、安全框與播放器；按住圖片拖曳期間，圖片與安全框不應閃爍或消失，放開後虛線框狀態正確。
- [ ] 儲存專案、完全關閉程式、再開啟 `.subtool`：圖片的來源、In/Out、時間軸位置、大小與位置均保留。純圖片專案在之後再匯入第一支影片時也不能遺失。
- [ ] 匯出一段圖片位於中段或超過一秒的影片：整段都持續顯示圖片，位置與大小須與播放器一致；不可只輸出開頭第一張畫面。
- [ ] 打開播放器的 `TC`：一般 HTML 預覽與 mpv 預覽都要顯示與播放器大時碼相同的讀數；關掉後不殘留虛線框、控制點或 TC。
- [ ] 匯出視窗勾選「壓入時間碼浮水印」：輸出檔左上角顯示由輸出 `[In]` 開始的時碼，數字等寬；未勾選時輸出檔不可含 TC。WAV 匯出不可出現此選項。

### 10. 字幕文字檢查、範圍與操作紀錄（v4.6.1）

- [ ] 文字檢查遇到明確簡體或非繁中／英文／數字／符號字元時，字幕編號為紅色；只含「后、干、台、里」等繁簡共用字時，字幕編號為黃色，hover 可看到人工確認原因。
- [ ] 設定／清除播放器 `[In]`、`[Out]` 後，動作紀錄會出現相應項目；`Ctrl+Z`／Redo 可還原範圍，匯出預覽的起訖也同步改變。
- [ ] 按住 Alt 拖曳字幕區塊：原字幕不移動，放開位置新增一份複本；一般拖曳仍為移動。
- [ ] 以右鍵點擊播放速度，選「自訂速度」後能輸入並套用 0.1x–4x 的數值；取消不改變目前速度。

### 11. 母素材匯出、音訊 bitrate 與匯出效能（v4.6.2）

- [ ] 以具多聲道母素材（例如 MXF／MOV）匯出 MP4：完成通知應顯示「音訊 AAC 實測」，Mono 目標約 192k、Stereo 約 320k、5.1 約 640k；不可顯示播放快取 `chN.m4a` 的 128k 規格。
- [ ] 將專案音訊配線為多條 Mono 後，以 ffprobe／播放器檢查每條輸出 stream 的 bitrate；確認是本次 MP4 的 AAC 交付 bitrate，而不是來源／Proxy bitrate。
- [ ] 匯出畫面與音訊同來自同一個大型素材時，觀察 ffmpeg 日誌／系統 I/O：素材應只開啟一次並同時供影像與音訊 filtergraph 使用，不可為音訊再建立第二個同路徑輸入。
- [ ] 在影片匯出視窗按「聲道設定」後按取消：必須回到匯出視窗，且先前選擇的格式、MP4 Mbps 與 TC 勾選狀態仍保留。

### 12. 全檔案註釋補強、軌道點選與鍵盤導航（v4.6.3）

- [ ] 點選時間軸空白處（軌道區域）：應清空當前選擇，並自動將該軌記錄為 Active Track。
- [ ] 字幕軌模式下按 `↑`／`↓` 方向鍵：應直接將焦點與播放頭跳轉並選取該軌內的上一條／下一條字幕。
- [ ] 狀態列 (`statusbar`)：底部空間乾淨空曠，原按鈕已全數搬移至頂部選單列 (`menubar`) 右側。

## 出問題怎麼回報

- **DevTools console** = renderer（前端）錯誤
- **終端機 2（Electron）** = main 行程 / ffmpeg 錯誤
- 把紅字訊息貼出來即可

## 預期效能

- **第一次**開檔會等單次轉碼完成（GPU 下 MXF 約 4–5 分、MOV 約 7–12 分，主要受讀取大檔的硬碟 I/O 限制）。
- **第二次以後**同一支片由快取秒開。

## 設計上的取捨（已知、非 bug）

- 採「單次讀取 + 進度條 + 快取」，**沒有**做「轉檔途中即可編輯」（那需要 HLS 串流，會造成時間軸累積漂移 5.9–7.4 秒，對逐格字幕是大忌，故不採用）。
- 單一音訊素材一次只顯示 MIX 或一條指定來源聲道的波形；這是顯示選擇，不會改變專案路由或輸出。
- 聲道分組（5.1 / 2.0）無法從中繼資料可靠判斷（檔案 channel_layout 常為 unknown），故一律逐聲道攤開，由使用者自行判斷。
