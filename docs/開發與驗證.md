# SUB Tool 開發與驗證

本文件依開發、驗證、打包與安裝的順序提供操作方式。模組與資料流見[技術架構說明](技術架構說明.md)，原生介面見[Electron 維護手冊](Electron_維護手冊.md)，使用者操作見[使用說明](使用說明.md)。

開始修改前讀完根目錄 `AGENTS.md` 與[技術鐵律](技術架構說明.md#0-鐵律invariants)。牽涉時碼、seek、逐格或播放點時，再讀 [FPS／時碼一致性](FPS_時碼一致性.md)。

## 1. 指令

### 前置需求

CI 使用 Node.js 24 與 npm。Windows 正式桌面流程以 Windows x64 為目標；Apple Silicon 驗收需要實體 M 系列 Mac。先安裝鎖定依賴：

```bash
npm ci
```

桌面 runtime、建置器與測試工具的實際版本以 `package-lock.json` 為準。依賴更新後，除了 `npm audit`，也要驗證 Vite 開發模式的 shared CJS 載入、Electron 原生視窗／播放與實際封裝內容。

Electron 44 的 npm 套件在第一次使用時才下載 runtime。本專案的 `postinstall` 明確準備 runtime，讓正常 `npm ci` 後可直接執行桌面驗收；`npm test` 的 `pretest` 與 Windows CI 測試入口也會核對準備。若安裝時使用 `--ignore-scripts`，執行桌面流程前須先執行 `node node_modules/electron/install.js`。下載失敗時應先修復下載，再執行桌面測試。

`package.json` 的兩項 `overrides` 是上游相依的修補邊界：`global-agent` 升至 4.1.3 以上，保留 `@electron/get` 使用的 `bootstrap()` 與環境變數代理介面，移除舊版帶入的 `roarr`／`sprintf-js`；`brace-expansion@^5.0.0` 至少使用 5.0.12，只約束第 5 版分支，避免破壞其他工具使用的第 1／2 版介面。更新時須核對實際依賴樹；代理相容性應由 `@electron/get` 真正下載並比較內容，不能只檢查 export 存在。上游移除舊依賴或自行要求修補版本後，重新驗證並移除不再需要的覆寫。

網頁開發執行 `npm run dev`。桌面熱更新須先啟動該伺服器，再於另一個終端執行 `npm run electron:dev`；主程序的開發網址為 `http://localhost:8777/`。

| 指令 | 結果或用途 |
|---|---|
| `npm run dev` | 啟動 Vite 開發伺服器 |
| `npm run preview` | 預覽目前 build |
| `npm run electron:dev` | 以 `--dev` 連接開發伺服器 |
| `npm run electron` | 先 build，再啟動 Electron |
| `npm run lint` | ESLint 檢查 `src electron shared scripts` |

| `npm run native:prepare:disc` | 準備固定來源與雜湊的 Windows 光碟工具 |

| `npm run release:prepare -- …` | 版號與 changelog 交易 |

基本檢查依序執行：

```bash
npm run lint
npm test
npm run build
rg "from './app.js'" src
```

最後一項應無符合結果。測試數量以當次輸出為準，不把歷史通過數量當成目前保證。

開發模式也要驗證。`vite.config.mjs` 讀取 shared 目錄建立 CJS 預打包清單；`tests/viteSharedDevelopment.test.js` 經真實 Vite 伺服器核對 caller 與 named exports，防止 build 成功但 dev 無法載入。

CI 分為 Ubuntu 的 lint／portable tests／build，以及 Windows 的 native 工具準備／build／windows tests。Windows 工作先核對完整 FFmpeg 下載檔的固定 SHA-256，再準備光碟工具；CI 不執行 electron-builder 發版。直接啟動 Electron 或依賴 Windows 封裝 FFmpeg 的測試，檔頭須有 `// @subtool-ci windows`，由 `tests/ciWorkflow.test.js` 檢查分類。Vitest 的 test／hook timeout 目前均為 30 秒，不能以延長 timeout 取代內容與生命週期核對。

## 2. 建置與發版流程

### Windows 正式發版

正式發布須讓來源、manifest、最新紀錄、Setup、安裝版與 GitHub asset 對應同一版。

1. 完成 lint、test、build，以及受影響功能的真實 Electron／原生工具驗收。
2. 在系統 temp 建立 notes，寫問題原因、行為變更及證據。須有非空的 `### 驗證` 區段，不自行加入另一個版本標題。
3. 執行唯一的版號／changelog 修改入口：

   ```bash
   npm run release:prepare -- --version X.Y.Z --date YYYY-MM-DD --notes <notes檔路徑>
   ```

   `release-transaction.js` 只更新兩份 manifest 的當前版號，並在 changelog 導言後插入單一新區段。它從 Git 取得正式來源證據，包含 `src/`、`electron/`、`shared/`、`scripts/`、根目錄 `index.html` 與 `vite.config.mjs`。版號須是無前置零、各分量為安全整數且高於目前版本的 `X.Y.Z`。任一檔寫入失敗會回復本次交易。

4. 已 prepare、尚未提交或建立 tag 的版本若補入修復，可用相同版號、日期與 `--replace-current true` 更新最新 notes；該版本須高於 Git HEAD。此模式保留原標題、日期、manifest 及歷史區段，不改寫已發佈版本。
5. 對最終內容重新驗證並打包：

   ```bash
   npm run lint
   npm test
   npm run build
   npm run release:verify-source
   npm run dist
   ```

   `predist` 會再驗來源與 Windows x64 native 檔案。正式包須包含 ffmpeg、ffprobe、mpv、`d3dcompiler_43.dll` 及 `electron/disc-tools.json` 列出的工具和授權檔；先以 `npm run native:prepare:disc` 準備光碟工具。

6. 記錄新 Setup 的大小及 SHA-256，正常執行 Setup 安裝到 Program Files。可使用正常 `/S` 靜默安裝，**正式驗收不可使用 NSIS `/D` 改目的地，更不可安裝到 repo**。
7. 核對安裝 EXE 的 FileVersion／ProductVersion、解除安裝 DisplayVersion、桌面與開始功能表捷徑、`.subtool` 關聯，以及 App 內版本。確認啟動的是安裝目錄的程式，對安裝版重跑受影響的內容驗收。
8. 執行 `npm run release:verify-install`。這是 repo 路徑安全檢查，不能代替版本、內容及捷徑完整性驗收。
9. 逐檔確認本版修改，以繁體中文提交訊息提交，再 push `main`。混有其他工具或使用者修改時，禁止直接 `git add -A`。
10. 建立 `vX.Y.Z` tag 與非 draft、非 prerelease 的 GitHub Release，上傳剛才實際安裝及驗證的同一支 Setup。
11. 核對遠端 asset 的檔名、大小與 SHA-256 digest。API 沒有 digest 時，重新下載該 asset 計算雜湊。

不可全域取代版號。歷史版本與內文交叉引用是事實紀錄；文件標頭不寫當前版號，當前值以 `package.json` 為準。只更新文件時核對連結與內容即可，不因此宣稱已有新安裝版。

### Apple Silicon 本機測試版

```bash
npm ci
npm run dist:mac:test
```

此命令先準備及檢查 arm64 工具、build，再以 unsigned／未啟用 hardened runtime 的設定建立：

- `release/SUB Tool-<版本>-mac-arm64.dmg`
- `release/SUB Tool-<版本>-mac-arm64.zip`
- `release/mac-arm64/SUB Tool.app`

只供本機驗證，不能直接上傳正式 Mac Release。對外發布仍須 Developer ID 簽署、hardened runtime、Apple notarization 與實體 Mac 驗收。目前測試包不含 mpv 或 Windows 光碟工具；MXF 走 ffmpeg ingest／Proxy。Windows 的 mpv 結果不能當作 Mac 驗證。

### 安裝器 smoke 的安全邊界

封裝檢查使用獨立 temp，App 驗收使用獨立 profile；完全隔離安裝應在測試機或隔離系統內跑正常 Setup。不要以 `/D` 導向 repo 模擬安裝。

清理前解析暫存絕對路徑、核對歸屬並等待自有程序關閉。不得以廣泛刪除、`git reset --hard` 或 `git checkout --` 恢復工作樹。

## 3. 真機驗證（CDP）

單元測試不能證明 mpv 畫面、原生輸入與輸出內容正確。依序建立獨立 profile、啟動、等設定初始化、建立 fixture、操作及核對內容，最後關閉連線和自有程序。

**獨立 `--user-data-dir` 必須搭配 `--subtool-transport-acceptance`。** 開發版只有前者仍會共用 repo `.config`；acceptance flag 才把設定移到該 profile，並停用母素材旁 sidecar cache。fixture 應在設定載入後建立，避免被遲到設定覆蓋。

```powershell
$profileDir = Join-Path $env:TEMP ('subtool-cdp-' + [guid]::NewGuid().ToString('N'))
& ".\node_modules\electron\dist\electron.exe" . --subtool-transport-acceptance --remote-debugging-port=9222 --user-data-dir="$profileDir"
```

驗正式安裝版時改用 Program Files 的 EXE，保留隔離 profile 與 acceptance flag。部分腳本支援 `SUBTOOL_ACCEPTANCE_EXE`；只對實際支援的腳本設定，並核對 App 內版本及安裝 ASAR。

`scripts/acceptance/cdp-electron-harness.js` 管理共用連線及程序生命週期。HTTP、WebSocket 建連、命令與輪詢各有期限；命令預設五分鐘，個別案例可縮短。`waitFor()` 期限包含單次非同步讀取，不能接受逾時後的 ready。逾時不代表底層操作已取消，caller 仍須在 finally 關閉 CDP。以 `trackElectron()` 登記完整 `close`，清理 profile 前 `await stopElectron()`；停止逾時須回報失敗。Windows 清理可有界重試，每次仍核對目標路徑。

| 腳本（位於 `scripts/acceptance/`） | 核對內容 |
|---|---|
| `cdp-run.js <頁面腳本> [port]` | 已啟動主頁面執行 JS，等待非同步結果並轉發 console |
| `verify-transport-smoothness.js <素材路徑…>` | 播放、seek、逐格與按住方向鍵 |
| `verify-preview-working-set.js` | mpv／WebCodecs 預熱、接管、淘汰及大量字幕預覽 |
| `verify-reverse-shuttle.js` | 長 GOP seek、倒帶、Proxy 切換及漂移 |
| `verify-locked-media-selection.js` | 鎖定視／音軌選取保留及播放點拖曳 |
| `verify-locked-subtitle-editing.js` | 鎖定字幕內容、時間及樣式保護 |
| `verify-subtitle-style-selection.js` | 樣式篩選、可見列選取、搜尋及鎖定選取 |
| `verify-speech-recognition-ui.js` | 辨識／文本匹配視窗、寬窄版及對齊 |
| `verify-recognition-audio-source.js` | 實際上傳音訊、來源聲道、原稿及時間 |
| `verify-vocal-waveform.js` | 真實模型、來源對齊、原波形保留、取消重試及持久快取；首次需模型下載 |
| `verify-transcript-txt-import.js` | 逐行 TXT 匯入 |
| `verify-media-context-menus.js` | 右鍵選單、速度／反轉聲音、固定畫面、幾何、Undo 及正式保存重開 |
| `preview-queue-window.js` | 佇列大、中、小版面 |
| `verify-mod-fhd.js` | 正式計畫及 watchdog 的場序、TS 與音訊 |

例如：

```bash
npm run build
node scripts/acceptance/verify-transport-smoothness.js "C:/Media/驗收素材.mp4"
node scripts/acceptance/verify-reverse-shuttle.js
```

### 文件截圖

node scripts/acceptance/capture-documentation-workspace.js docs/images/workspace-overview.png

工作區截圖使用目前 build 與不含私人素材的展示狀態。辨識截圖先留系統 temp，檢查後再複製到 `docs/images/`；佇列預覽用真實瀏覽器確認 980px、620px 斷點。

驗證時保留以下限制：

- mpv 是 OS 視窗，`Page.captureScreenshot` 不會拍到它；主畫面截圖先確認實際 presenter。
- 原生 modal 可能擋住頁面合成。比較是否同列應比控制項垂直中心，不能只比盒頂。
- CDP 斷線必須使未完成驗收失敗，不能將缺少回覆當成成功。
- 檔案存在、命令 exit 0 或畫面有反應，不能代替像素、PCM、時碼及 metadata 檢查。
- **絕不在 repo 根目錄跑 `asar extract-file`**。它按 basename 寫 cwd，曾兩次覆蓋來源 `index.html`，lint／test／build 仍全綠。先切獨立 temp 再解；`tests/sourceEntryHtml.test.js` 紅燈時先檢查來源是否被產物覆寫。

## 4. 大檔人工驗證清單

### 4.1 共用

- [ ] 首次顯示 probe／intake 進度，再次核對完整快取命中。
- [ ] FPS 由 ffprobe 或實際來源取得，不能看檔名猜測。
- [ ] 播放、暫停、長距離 seek、左右單格與連續逐格，核對實際畫格、時碼及播放點。
- [ ] J／K／L、1×–5×、倒帶靜音及停止後回母素材正確。
- [ ] Proxy 期間音量／靜音有效；取消與換專案停止舊工作，重試可完成且不誤停交付。
- [ ] seek 等待期間無舊聲音提前啟動，定位後無重播疊音。
- [ ] 鎖定軌保留選取、允許定位，內容修改仍受保護；見[使用說明](使用說明.md#鎖定軌的定位規則)。
- [ ] 來源聲道、波形、M／S／音量及路由符合實際內容。
- [ ] HTML、mpv 與燒錄字幕的文字、字型、位置、背景及換行一致。

### 4.2 參考素材

### 4.3 MXF／MOV／MP4

- [ ] MXF stream／channel 展開與 UI 一致，5.1＋2.0 不被降混。
- [ ] Proxy 完成後接管及同來源指紋快取可重現。
- [ ] MOV ProRes 10-bit、5.1、中後段逐格及來源原點正確。
- [ ] MP4 原生與 WebCodecs 疊層均可 seek，大檔不整支載入記憶體。
- [ ] 交付影像及音訊讀母素材，不讀 Proxy／波形／聲道快取。

### 4.4 匯出

- [ ] 九種格式各驗一份：ProRes422HQ-MOV、H264-MP4、WAV、DVD-ISO、BD-ISO、MOD-FHD、DMPES 1.5M／4M、exW 500K。
- [ ] ffprobe 核對 codec、尺寸、FPS、片長、bitrate 及 layout，解碼核對畫面與 PCM。
- [ ] 來源聲道 7／8 分配 Stereo 左／右後內容相符且非意外靜音，較長聲道尾音不截斷。
- [ ] DVD／BD 無選單、首播 title 1，容量、UDF、目錄及 `DVD`／`BD` 標籤正確。
- [ ] BD 依來源選模式：23.976／24 為 1080p，25／29.97 為 1080i，最高 29.97。
- [ ] MOD-FHD 核對 TS、TFF 及音訊；無既有平衡時核對 −12 dBTP 上限與非靜音約 −18 LUFS，既有設定不重複套用，純靜音仍無聲。
- [ ] 航空 `.mpg` 是可解碼 MPEG-TS；DMPES 720×480／16:9，exW 640×360／正方形像素／AFD 10／VBR 500 kbps 視訊與 64 kbps AAC。
- [ ] 航空成品核對影音同步、MediaInfo delay 及 Manzanita TSA；參數對應或診斷檔不代替正式交付驗收。
- [ ] In／Out 符合實際半開區間格數與片長。
- [ ] 同路徑只有一個 live writer；取消／崩潰不刪原有同名成品。
- [ ] 重啟能復原 stale lease、清本工作私有半成品並保留可重試紀錄。
- [ ] 有執行工作時關主視窗由監控接手；真正退出等 native close 與 owner 收尾。

### 4.5 Apple Silicon

- [ ] App、封裝 ffmpeg 與 ffprobe 均為 arm64。
- [ ] `status()` 回報 darwin／arm64 及可用工具，`mpv.detect()` 明確回報不支援。
- [ ] 實體 Mac 驗收 H.264 MP4、真實 MXF、多聲道 MOV、圖片、字幕拖曳及支援的交付。
- [ ] DMG／ZIP 未混入 Windows exe 或 mpv。

## 5. 問題回報

提供操作、預期及實際結果、素材格式／大小／FPS／聲道、問題時間碼、renderer console、main／ffmpeg log，以及最小專案或診斷輸出。背景問題另附 session、request 或 job id。

診斷只解釋量到的範圍：輸入 probe 的事件建立至 handler 延遲仍可能含 renderer JS 排隊；五位置讀取只提供該次 I/O 線索，不能單獨判定 moov、SMB、mpv 佔用或原生對話框原因。

來源聲道依 stream／channel 展開，不依不可靠的群組名稱猜測。首次建立快取需時間，只有完整且來源證據相符的快取才能重用。串流與精準呈現仍遵守[時間權威](FPS_時碼一致性.md)，可播 URL 不代表已定位完成。

## 6. 目錄結構與命名

| 位置 | 職責與命名 |
|---|---|
| 根目錄 | 入口、套件設定、共用規則與啟動器，不放一次性實驗 |
| `src/` | renderer ESM，`kebab-case.js` |
| `electron/` | main、preload、native adapters 及獨立視窗，`kebab-case.js` |
| `shared/` | 零相依純 CommonJS 領域規則，`kebab-case.cjs` |
| `tests/` | Vitest 行為、契約與結構測試，`lowerCamelCase.test.js` |
| `scripts/acceptance/` | CDP、原生內容及真機驗收 |
| `scripts/ci/` | package scripts 使用的 CI 分組 |
| `scripts/diagnostics/` | 人工診斷，檔頭保留可複製用法 |
| `scripts/release/` | 發版交易、native 準備及安裝驗證 |
| `docs/` | 依 AGENTS 文件職責分流，沿用既有中文名稱 |
| `font/<顯示名>/` | 自備字型；資料夾名供 UI 顯示，內部 family 仍由字型檔取得 |

`dist/`、`release/` 建置中間產物、`node_modules/`、native 工具及媒體快取可由各自流程重建；這不構成任意刪除現有安裝包、工具、使用者資料或素材的授權。

新增頂層項目須更新 `tests/repositoryStructure.test.js` allowlist；文件入口依 AGENTS 職責表及 README 索引處理。一次性實驗放系統 temp，需要長期守住的案例改成測試。`src/logo.png` 與 `electron/logo.png` 是兩端 adapter 刻意保留的資源，不能只因 bytes 相同刪一份。

## 7. 靜態安全網

Lint 擋未定義名稱及封裝違規，build 擋缺少 export，tests 驗行為及資料，內容驗收再核對實際產物；各層不能互相取代。

- 選取狀態只經 `setSelection`、`deselect`、`pruneSelection`、`focusTrackKind` 修改。
- `Media._*` 只供 `eslint.config.mjs` 的 `MEDIA_INTERNAL_FILES` 使用，其他 caller 走公開介面。
- 低階模組不得 import `app.js`，改用 `events.js` 通知上層，並驗證有訂閱者。
- 新增頂層程式目錄同步加入 lint 參數；CJS／Node ESM scripts 都須有正確 globals。
- flat config 的 `no-restricted-syntax` 會整組取代，兩道圍籬不得互相覆蓋。

規則以 [AGENTS.md §7](../AGENTS.md#7-靜態安全網) 為準。

## 8. 常見陷阱

| 現象或操作 | 契約 |
|---|---|
| Electron 輸入對話框 | 使用 `promptModal()`，不能依賴 `window.prompt()` |
| 本機字型或媒體被擋 | 保持 `webSecurity:true`，使用 FontFace 與受控資源 URL |
| mpv 與 HTML 互動 | mpv 是 OS 視窗，沿用 renderer layer／guide 分工 |
| `[hidden]` 仍顯示 | 作者 CSS 可覆蓋 UA 規則，查 computed style 並補元件規則 |
| 字幕預設及三路呈現 | 預設由 `STYLE_DEFAULTS`，生效結果由 `effStyle()` 統一 |
| Windows filtergraph 路徑 | 使用既有兩層跳脫，不能只處理一般 shell 路徑 |
| ASS 字型 | Fontname 使用字型內部 family，不用資料夾顯示名 |
| ASAR 核對 | 先切獨立 temp，再 extract；來源入口須仍為原始碼 |
