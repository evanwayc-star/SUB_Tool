# SUB Tool 開發與驗證

這份文件是環境、指令、真機驗收與發版流程的唯一細節來源。架構規則請看 [技術架構說明](技術架構說明.md)；桌面整合請看 [Electron 維護手冊](Electron_維護手冊.md)。

動手前先讀：

1. 根目錄 `AGENTS.md`
2. [技術架構說明 §0](技術架構說明.md#0-鐵律invariants)
3. 改 seek、播放點或逐格時，再讀 [FPS／時碼一致性](FPS_時碼一致性.md)

## 1. 指令

### 前置需求

- Node.js 20 或更新的 LTS
- npm
- Windows 正式桌面驗收：Windows 10／11 x64
- Apple Silicon 測試：實體 M 系列 Mac

```bash
npm ci
```

| 指令 | 用途 |
|---|---|
| `npm run dev` | Vite 網頁開發伺服器 |
| `npm run electron:dev` | Electron 開發模式 |
| `npm run electron` | 先 build，再開啟 Electron |
| `npm run lint` | 檢查 `src electron shared scripts` |
| `npm test` | 全部 Vitest |
| `npm run build` | 產生單一 `dist/index.html` |
| `npm run test:ci:portable` | 跨平台測試群組 |
| `npm run test:ci:windows` | Windows／Electron 測試群組 |
| `npm run dist` | Windows x64 NSIS 安裝包 |
| `npm run dist:mac:test` | Apple Silicon unsigned 測試包 |

基本守門：

```bash
npm run lint
npm test
npm run build
rg "from './app.js'" src
```

最後一行結果必須為空。

## 2. 建置與發版流程

### Windows 正式發版

發版不是「有一支 exe」；版本、來源、安裝、App 內版本、遠端 Release 與雜湊都要一致。

1. 完成 lint、test、build。
2. 以真實 Electron、mpv、MOV、MXF 與逐格操作驗收。
3. 建立只含「為什麼」與「怎麼驗」的暫存 notes 檔。
4. 執行：

   ```bash
   npm run release:prepare -- --version X.Y.Z --date YYYY-MM-DD --notes <notes檔>
   ```

   這是唯一可修改版本與 changelog 的入口。它只更新 `package.json`、`package-lock.json`，並在 changelog 導言後新增一個版本區段。

5. 再跑：

   ```bash
   npm run lint
   npm test
   npm run build
   npm run release:verify-source
   npm run dist
   ```

6. 正常執行新 Setup。不要用 NSIS `/D` 當正式驗收；那會破壞捷徑與解除安裝 metadata。
7. 確認安裝位置、桌面捷徑、開始功能表、解除安裝項目與 App 內版本。
8. 執行：

   ```powershell
   npm run release:verify-install
   ```

9. 只 stage 本版確認過的檔案，使用繁體中文提交訊息；工作樹混有其他工具變更時禁止 `git add -A`。
10. Push `main`、建立 `vX.Y.Z` tag 與非 draft GitHub Release，上傳同一支 Setup。
11. 重新下載遠端 asset，比對本機與遠端 SHA-256。

注意：

- 不可對版號做全域字串取代。
- changelog 內舊版本是歷史證據，永遠不改寫。
- `release:verify-source` 在 annotated tag 轉換點可能需要核對 tag target；不可只用單一 exit code 判定封裝內容。
- 正式 Windows 包必須含 ffmpeg、ffprobe、mpv 與 `d3dcompiler_43.dll`。

### Apple Silicon 本機測試版

```bash
npm ci
npm run dist:mac:test
```

產物：

- `release/SUB Tool-<版本>-mac-arm64.dmg`
- `release/SUB Tool-<版本>-mac-arm64.zip`
- `release/mac-arm64/SUB Tool.app`

這只是 unsigned 測試版，不是正式發佈。對外發佈前仍需 Developer ID 簽署、hardened runtime、Apple notarization 與實體 M 系列 Mac 完整驗收。

第一階段 macOS 不封裝 mpv，MXF 走 ffmpeg ingest／Proxy。不可宣稱 Windows 的三路 mpv 驗證已在 Mac 完成。

### 安裝器 smoke 的安全邊界

- 使用獨立暫存資料夾與 profile。
- 不要覆寫使用者正式安裝與 userData。
- 只清理已解析、已確認的暫存絕對路徑。
- 不要用 `git reset --hard`、`git checkout --` 或廣泛刪除恢復工作樹。

## 3. 真機驗證（CDP）

Vitest 可驗純規則，不能證明 Electron、mpv、原生輸入或實際呈現正確。重要互動要用獨立 profile 啟動 Electron，再以 CDP 操作。

```powershell
& ".\node_modules\electron\dist\electron.exe" . --remote-debugging-port=9222 --user-data-dir="$env:TEMP\subtool-cdp-profile"
```

| 腳本 | 驗證 |
|---|---|
| `scripts/acceptance/cdp-run.js` | 對已啟動 Electron 執行 in-page 驗收 |
| `verify-transport-smoothness.js` | 播放、seek、逐格與按住方向鍵 |
| `verify-reverse-shuttle.js` | 長 GOP seek、倒帶、Proxy 切換與漂移 |
| `verify-locked-media-selection.js` | 鎖定視／音軌的選取保留與播放點拖曳 |
| `verify-locked-subtitle-editing.js` | 鎖定字幕軌內容、時間與樣式不可修改 |
| `verify-speech-recognition-ui.js` | 語音辨識／文本匹配寬窄版與對齊 |
| `verify-recognition-audio-source.js` | 辨識來源聲道選擇 |
| `verify-transcript-txt-import.js` | 逐行 TXT 匯入 |
| `verify-media-context-menus.js` | 媒體右鍵選單 |
| `preview-queue-window.js` | 匯出佇列大、中、小版面 |

典型播放驗收：

```bash
npm run build
node scripts/acceptance/verify-transport-smoothness.js
node scripts/acceptance/verify-reverse-shuttle.js
node scripts/acceptance/verify-locked-media-selection.js
node scripts/acceptance/verify-locked-subtitle-editing.js
```

### 文件截圖

```bash
npm run build
node scripts/acceptance/capture-documentation-workspace.js docs/images/workspace-overview.png
node scripts/acceptance/verify-speech-recognition-ui.js
node scripts/acceptance/preview-queue-window.js
```

- 工作區截圖由目前 `dist` 與不含私人素材的展示狀態產生。
- 語音辨識腳本把截圖寫到系統 temp，確認後再複製到 `docs/images/`。
- 佇列腳本產生預覽 HTML；需要用真實瀏覽器視窗檢查 980px、620px 斷點。
- mpv 是 OS 視窗，`Page.captureScreenshot` 不會拍到它。拍主畫面前要確認預覽由 HTML／WebCodecs 呈現。

驗證方法本身也可能錯：

- mpv 畫面不在 CDP 截圖中。
- 原生 modal 會擋住頁面合成。
- 用盒頂座標比較「是否同列」會被不同控制項高度誤導；應比垂直中心。
- 只看命令成功、檔案存在或畫面有反應，不能證明內容正確。
- 不可在專案根目錄執行 `asar extract-file`；它會依 basename 覆寫來源 `index.html`。

## 4. 大檔人工驗證清單

### 4.1 共用

- [ ] 第一次載入顯示 probe／ingest 進度，第二次命中快取。
- [ ] FPS 來自 ffprobe 或實測，不依檔名。
- [ ] 播放、暫停、長距離 seek、左右逐格與按住連續逐格都立即更新畫面。
- [ ] 播放點、播放器時碼與實際呈現畫格一致。
- [ ] J／K／L、1×–5×、倒帶靜音與停止後回母素材正確。
- [ ] 鎖定視／音／字幕軌仍可點擊和拖曳播放點，但內容不可被選取或修改。
- [ ] 波形、所有來源聲道、M／S／音量與輸出路由正確。
- [ ] HTML、mpv 與燒錄字幕的內容、位置、字型、背景與換行一致。

### 4.2 參考素材

參考資料夾：`C:\Users\Evan\Desktop\參考資料`

| 素材 | 主要驗收 |
|---|---|
| `V_MAMAMOO_FTR_24fps_51FM.mov` | 超大型 ProRes／MOV、24fps、5.1、長距離 seek 與逐格 |
| `V_拼桌_FTR_24FPS_51FM+20FM_30P.mxf` | 44GB MXF、多音軌、檔名與實測 FPS 不一致、Proxy 與快取 |
| `V_心機特務_FTR.mp4` | 4GB MP4、瀏覽器原生／桌面播放器切換與長片 seek |

三支都要測；小型合成素材不能取代這組實際母檔。

### 4.3 MXF／MOV／MP4

- [ ] MXF 的 stream 順序與 UI 來源聲道一致，5.1＋2.0 不可被降混。
- [ ] MXF Proxy 完成後自動接管，第二次開啟使用相同來源指紋快取。
- [ ] MOV ProRes 10-bit 畫面與 5.1 聲道正確，中後段逐格不會停在同一格。
- [ ] MP4 原生播放與 WebCodecs 多層合成都可 seek，大檔不整支讀入記憶體。
- [ ] 匯出影像與音訊都讀母素材，不讀 Proxy 或逐聲道快取。

### 4.4 匯出

- [ ] MP4、ProRes、WAV 各完成一份。
- [ ] 用 ffprobe 檢查 codec、解析度、FPS、時長、bitrate 與 channel layout。
- [ ] 來源聲道 7／8 分配到 Stereo 左／右後，兩邊內容正確且非靜音。
- [ ] `[In]`／`[Out]` 顯示與實際輸出時長一致。
- [ ] 同一輸出路徑不可同時有兩支 ffmpeg。
- [ ] 強制結束後，重啟會清半成品與 stale lease，工作回到可恢復狀態。
- [ ] 主視窗關閉但有執行中工作時，佇列監控接手；不可靜默中止工作。

### 4.5 Apple Silicon

- [ ] App 與封裝 ffmpeg／ffprobe 都是 arm64。
- [ ] `window.subtool.status()` 顯示 `darwin`、`arm64` 與可用 native tools。
- [ ] `window.subtool.mpv.detect()` 明確回傳不支援。
- [ ] H.264 MP4、真實 MXF、多聲道 MOV、圖片、字幕拖曳與交付都在實體 Mac 驗收。
- [ ] DMG／ZIP 不含 Windows exe 或 mpv 檔。

## 5. 問題回報

請提供操作步驟、預期結果、素材格式／大小／FPS／聲道、DevTools 紅字、Electron／ffmpeg log、問題時間碼，以及可重現的最小專案或診斷輸出。

已知取捨：

- 首次大檔會建立 Proxy、波形與聲道快取；第二次才會秒開。
- 不做「Proxy 尚未完成就開始精準剪輯」的 HLS 方案，避免長片時間軸漂移。
- 聲道群組 metadata 不可靠，因此來源聲道依 stream／channel 順序展開。

## 6. 目錄結構與命名

| 位置 | 唯一職責 | 命名 |
|---|---|---|
| 根目錄 | 入口、套件設定、共用規則與三支啟動器 | 不放實驗或暫存檔 |
| `src/` | renderer ES 模組 | `kebab-case.js` |
| `electron/` | 主行程、preload、native adapters 與獨立視窗 | `kebab-case.js` |
| `shared/` | 兩行程共用的零相依純 CommonJS 規則 | `kebab-case.cjs` |
| `tests/` | Vitest 行為、契約與結構測試 | `lowerCamelCase.test.js` |
| `scripts/acceptance/` | CDP 與真機驗收 | Node 腳本 |
| `scripts/ci/` | CI 測試分組 | 只由 package scripts 呼叫 |
| `scripts/diagnostics/` | 人工診斷 | 檔頭寫可複製用法 |
| `scripts/release/` | 發版與安裝驗證 | 只由發版 scripts／測試呼叫 |
| `docs/` | 依 `AGENTS.md` 的單一文件職責分流 | 沿用既有中文檔名 |
| `font/<顯示名>/` | 自備字型 | 資料夾名是 UI 顯示名 |

`dist/`、`node_modules/`、`release/` 中間產物、`electron/ffmpeg/`、`electron/mpv/` 與快取都可重建，不是來源碼。

新增頂層檔案或資料夾時，必須同步更新 `tests/repositoryStructure.test.js` 的 allowlist 與 README 文件入口。一次性實驗放系統 temp；值得保留的結果改成測試。

`src/logo.png` 與 `electron/logo.png` 是兩個 runtime adapter 的刻意副本，不能只因內容相同就刪一份。

## 7. 靜態安全網

```bash
npm run lint
npm test
npm run build
rg "from './app.js'" src
```

另外確認：

- 選取狀態只能經 `setSelection`、`deselect`、`pruneSelection`、`focusTrackKind` 修改。
- `Media._*` 只能在 `media.js` 內使用；其他模組走公開介面。
- 新增頂層程式目錄時，同步加入 `npm run lint`。
- `events.js` 的事件沒有訂閱者會靜默 no-op；新增 emit 時要驗證訂閱。

## 8. 常見陷阱

- Electron 不支援 `window.prompt()`；使用 `promptModal()`。
- Chromium 的 `file:// @font-face` 會失敗；桌面字型以 FontFace API 與受控資源 URL 載入。
- 現行桌面安全設定為 `webSecurity: true`；本機檔案使用不透明 `subtool-local:` capability URL。
- mpv 是 OS 子視窗，HTML 疊層要由主視窗互動層或透明 guide 配合。
- CSS 作者規則可能蓋過 UA 的 `[hidden]`；有 `display` 的元件要補專用規則。
- 預設字幕樣式只由 `STYLE_DEFAULTS` 定義。
- Windows filtergraph 路徑需要兩層跳脫。
- ASS Fontname 必須是字型檔內部家族名。
- 驗 asar 時先切到獨立暫存目錄，絕對不要在專案根目錄跑 `asar extract-file`。
