# SUB Tool 開發與驗證

日常開發看 §1。Windows 正式發版與 Mac 本機包看 §2。改動播放、波形、聲道或交付時，用 §3 建立隔離環境，再從 §4 選素材與內容判準。搬移檔案前看 §6。[專案規則](../AGENTS.md) · [技術鐵律](技術架構說明.md#0-鐵律invariants) · [時間契約](FPS_時碼一致性.md)

## 1. 指令

### 前置需求

在專案根目錄使用 Node.js 24 與 npm，先執行 `npm ci`。版本以 `package-lock.json` 為準。`postinstall` 準備 Electron runtime，若曾用 `--ignore-scripts` 安裝，先執行 `node node_modules/electron/install.js`。下載失敗須先處理，再跑桌面測試。

開發或封裝畫面文字辨識還需要支援 Edition 2024 的 Rust／Cargo；Windows 需 MSVC C++ Build Tools 與 Windows SDK，Mac 需 Xcode Command Line Tools。在目標平台原生編譯，Windows x64 與 Mac arm64 的產物分開保管。安裝版使用者無須 Rust 或 Python。

| 工作 | 命令與判準 |
|---|---|
| 網頁開發 | `npm run dev` 啟動 Vite。`npm run preview` 預覽目前 build。 |
| 桌面開發 | 先 `npm run dev`，第二個終端執行 `npm run electron:dev`，連到 `http://localhost:8777/`。`npm run electron` 則 build 後啟動。 |

## 2. 建置與發版流程

### Windows 正式發版

1. 以最終功能改動執行 lint、test、build，並在真實 Electron 操作受影響入口。保存畫面、音訊或交付的比對證據。
2. 在系統 temp 寫 UTF-8 notes，含原因、行為、限制及非空 `### 驗證`。版本標題由工具產生。用以下命令升版，將版本、日期及 notes 路徑換成實際值。

   ```powershell
   npm run release:prepare -- --version X.Y.Z --date YYYY-MM-DD --notes "$env:TEMP\subtool-release-notes.md"
   ```

   `X.Y.Z` 必須高於目前版本，三個分量皆為無前置零的安全整數。此交易核對 Git 正式來源，更新兩份 manifest，將新區段插入 changelog 導言後。寫入失敗回復。來源含 `src/`、`electron/`、`shared/`、`scripts/`、`font/`、根 `index.html`、`vite.config.mjs` 或 manifest 實質變更。僅改文件、或僅改 manifest 的版號與 JSON 排版，均無正式來源證據。已備版但尚未提交、未打 tag，且版本高於 HEAD 時，用相同版號與日期加 `--replace-current true` 補最新 notes。歷史版號與交叉引用原樣保留。[交易程式](../scripts/release/release-transaction.js)
3. 依序重跑 `npm run lint`、`npm test`、`npm run build`、`npm run release:verify-source`。以 `npm run native:prepare:disc` 準備光碟工具，再執行 `npm run dist`。`predist` 會再核對來源與 x64 工具，並重新建置 Rust 畫面文字辨識引擎。[桌面封裝清單](Electron_維護手冊.md#7-打包與發布)
4. 記錄 `release/SUB Tool Setup X.Y.Z.exe` 的大小及 SHA-256。以此檔正常安裝到 Program Files，可用 `/S` 靜默安裝。正式驗收禁止以 NSIS `/D` 改目的地或安裝到 repo。
5. 啟動安裝目錄的 EXE，核對 FileVersion、ProductVersion、解除安裝 DisplayVersion、App 內版本、ASAR、桌面／開始捷徑與 `.subtool` 關聯。重跑受影響的原生功能。另執行 `npm run release:verify-install` 掃描指向 repo 的安裝資訊與捷徑。
6. 逐檔 stage 本版修改，繁中 commit 後 push `origin main`。在已驗證 commit 建立 `vX.Y.Z` tag 與正式 GitHub Release（非 draft／prerelease），上傳剛才安裝的同一份 exe。對照遠端檔名、大小及 SHA-256。API 沒有 digest 時，下載該 asset 計算。

### Apple Silicon 本機測試版

在實體 M 系列 Mac 執行 `npm ci`、`npm run dist:mac:test`。後者會先跑 `npm run native:prepare:mac`，驗 arm64 ffmpeg／ffprobe，再原生編譯 Rust 畫面文字引擎與 build，產生 `release/mac-arm64/SUB Tool.app` 與 `release/SUB Tool-<版本>-mac-arm64.{dmg,zip}`。測試包 unsigned，未啟用 hardened runtime。以 §4.5 驗本機內容；Rust 辨識核心亦須在實體 Mac 驗收，Windows 測試結果不代表 Mac 通過。正式 Mac Release 另需 Developer ID 簽署、hardened runtime、Apple notarization 與實體 Mac 驗收。

### 安裝器 smoke 的安全邊界

封裝檢查用獨立 temp，App 驗收用獨立 profile。完全隔離的安裝使用測試機。清理前等待自己的程序結束並核對暫存絕對路徑。勿用 `git reset --hard`、`git checkout --` 或廣泛刪除還原工作樹。

## 3. 真機驗證（CDP）

先 build，以獨立 profile 啟動，等設定載入才建立 fixture。完成或斷線都關閉 CDP 與本次自有程序。

```powershell
npm run build
$profileDir = Join-Path $env:TEMP ('subtool-cdp-' + [guid]::NewGuid().ToString('N'))
& ".\node_modules\electron\dist\electron.exe" . --subtool-transport-acceptance --remote-debugging-port=9222 --user-data-dir="$profileDir"
```

- **隔離設定**。開發版同時需要 `--user-data-dir` 與 `--subtool-transport-acceptance`，否則仍可能讀 repo 的 `.config`。acceptance flag 關閉素材旁快取。驗安裝版改用 Program Files 的 EXE，核對版本／ASAR。只有支援的腳本才讀 `SUBTOOL_ACCEPTANCE_EXE`。
- **驗素材旁快取**。只有在正式安裝版測真實 sidecar 寫入時才省略 acceptance flag。使用全新私有 profile 與本次 TEMP 素材，先核對封裝、設定根及空白專案／佇列。
- **連線與收尾**。共用 harness 限制 HTTP、WebSocket、命令與單次輪詢。命令預設五分鐘。逾時、斷線或遲到的 ready 使驗收失敗。在 `finally` 關閉 CDP，`trackElectron()` 登記 child，`await stopElectron()` 等到 `close` 才清 profile。[CDP harness](../scripts/acceptance/cdp-electron-harness.js)
- **原生畫面**。mpv 是 OS 視窗，CDP 截圖不含其內容。使用可見且未受遮擋的桌面、OS 合成像素與實際輸入，循序跑原生驗收。無人值守環境若誤判遮蔽並停止 rAF，可只對測試 child 加 `--disable-features=CalculateNativeWinOcclusion`，仍須測真正隱藏與最小化。

驗收腳本位於 [scripts/acceptance/](../scripts/acceptance/)。例如 `node scripts/acceptance/verify-transport-smoothness.js "C:/Media/驗收素材.mp4"`。

| 工作 | 腳本 |
|---|---|
| 連到既有頁面執行腳本 | `cdp-run.js <頁面腳本> [port]` |
| 播放、seek、倒帶、預熱 | `verify-transport-smoothness.js`、`verify-reverse-shuttle.js`、`verify-preview-working-set.js` |
| mpv 遮擋、滑鼠穿透與縮放 | `verify-native-overlay.js [安裝 EXE] [預期版號]` |
| 鎖軌、選取、字幕換行與右鍵編輯 | `verify-locked-media-selection.js`、`verify-locked-subtitle-editing.js`、`verify-subtitle-style-selection.js`、`verify-subtitle-line-break-contract.js`、`verify-subtitle-line-break-marker.js`、`verify-media-context-menus.js` |
| 辨識與字稿 | `verify-speech-recognition-ui.js`、`verify-screen-text-ui.js`、`verify-recognition-audio-source.js`、`verify-transcript-txt-import.js` |
| 畫面文字雲端短片實測 | `verify-screen-text-native.js <影片> <起點秒數> <長度秒數>`，最多 30 秒，需要可用 API 金鑰並會產生雲端費用；輸出留在 TEMP |

### 4.3 MXF／MOV／MP4

- 核對 stream／channel 展開及各路聲音，5.1＋2.0 保留原路由。原生與 WebCodecs 均測 seek，交付必須讀母素材。
- 從冷快取驗單次波形解碼、保存進度、完成 `wave.wav` 後才啟動 Proxy。前 20 秒每 5 秒來源 PCM 存一個檢查點，長度至少兩分鐘者其後每 30 秒，短片持續每 5 秒。檢查點使用來源時間。中斷後以新 profile 驗 `partial.wav` 與 `checkpoint.json`，將續算接點與整段 PCM 對照相同配方的完整樣本。接點不符可從起點驗前綴。[波形與快取契約](Electron_維護手冊.md#媒體-intake)
- 完整命中後檢查實際 FFmpeg 次數、聲道及 MIX，既有 WAV 不重做。換母素材、截短快取、改音訊配方或兩個 writer 同時完成時，應只補缺件且保留既有成果。唯讀 sidecar 只可重用，寫入失敗應提示並保留可驗證前綴。
- 相同 NAS 檔案按共享身分重用。不同複製檔或缺少可靠共享證據時要驗全文，只有相符 SHA 型紀錄才可跨檔重用。唯讀缺件提示無法寫入，不能改存本機。跨機用第二台實體電腦驗。同機第二 profile 只證明獨立設定重開。記錄前中後段內容、背景 console、CPU、main／renderer 延遲，分開量測擷取工具與工作本身。

### 4.4 匯出

完整交付驗收須將表列格式各交付一份，DMPES 1.5M、4M 分別驗。局部回歸依受影響格式選測。以 ffprobe 查 codec、尺寸、FPS、片長、bitrate、layout，再實際解碼核對下列內容。[格式與封裝](Electron_維護手冊.md#交付)

| 案例 | 內容判準 |
|---|---|
| ProRes422HQ-MOV、H264-MP4、WAV、MP3 | In／Out 為半開格區間。以可辨識的 A7／A8 聲音映射 Stereo L／R，核對來源→bus→交付配線、尾音、每份獨立編組。 |
| DVD-ISO、BD-ISO | 無選單、首播 title 1、標籤、容量、UDF、目錄。BD 23.976／24 為 1080p，25／29.97 為 1080i，上限 29.97。 |
| MOD-FHD | 核對 TS、TFF 與 PCM。無專案平衡時為 −12 dBTP 上限、非靜音約 −18 LUFS。有設定不重套，純靜音仍無聲。 |
| DMPES 1.5M／4M、exW 500K | `.mpg` 可解碼為 MPEG-TS。核對 DMPES 720×480／16:9 或 exW 640×360／正方形像素／AFD 10、視訊 VBR 500 kbps、64 kbps AAC。檢查影音同步、MediaInfo delay 與實際成品的 Manzanita TSA 掃描。 |
| 取消、崩潰、重啟 | 同路徑只有一個 writer。原有同名成品保留。復原舊 lease、私有半成品及可重試紀錄。關主窗由監控接手，退出等 native close 與 owner 收尾。 |

### 4.5 Apple Silicon

在實體 Mac 驗 App、ffmpeg、ffprobe 均為 arm64。`status()` 回 darwin／arm64 與可用工具，`mpv.detect()` 回不支援。DMG／ZIP 不含 Windows exe 或 mpv。實測 H.264 MP4、MXF ingest／Proxy、多聲道 MOV、圖片、字幕拖曳及支援的交付格式。

## 5. 問題回報

附操作、預期／實際、最小專案、素材格式／大小／FPS／聲道、問題時碼、renderer console、main／ffmpeg log。背景工作再附 session、request 或 job ID。

| 診斷入口（`scripts/diagnostics/`） | 如何解讀 |
|---|---|
| `node scripts/diagnostics/watch-cpu-and-lag.js <PID>` | 多個實例時指定 PID。共用 `main-inspector.js` 核對實際 PID、Electron 主行程與 App 名稱。9229 被占用時拒絕。一次一輪採樣，停止後只移除本次探針。 |
| `node scripts/diagnostics/measure-shell-metadata-read.js "<檔案完整路徑>"` | 量開檔與五個位置各最多 1 MB 的同步讀取。同素材不同播放狀態重測，單輪不能判定 moov、SMB 或 mpv 成因。 |
| `measure-dialog-stall.js`、`profile-renderer-stall.js` | 診斷對話框與 renderer 停頓。中止等現有 CDP 呼叫收尾，只釋放自己的攔截、計時器、listener、debugger。保留取消碼及失敗證據。輸入事件到 handler 的延遲可能含 renderer 排隊。 |

新增頂層項目，同步檢查 [repositoryStructure allowlist](../tests/repositoryStructure.test.js) 與 lint 的 CLI 目錄／config。一次性實驗放系統 temp。長期回歸放測試。新增文件類別同步更新 README 與 AGENTS 導覽。

### 整理與清理

先分辨 tracked、untracked、ignored 檔案與引用。保留最新 Setup、`release/latest.yml` 及現有 blockmap。`release/win-unpacked/`、`release/.icon-ico/`、`release/builder-debug.yml` 在安裝驗收結束且無程序使用才可清。`dist/index.html` 可重建，但仍供網頁啟動器與 build 模式驗收使用。

`.config/`、素材旁快取／自動備份屬設定、續算及復原資料。原生工具、依賴、字型與授權檔仍供執行或封裝。清理只限已確認目標，先解析絕對路徑並確認未跨 reparse point／連結。文件整理保留 changelog 歷史、ADR 日期與研究查核日期。

## 7. 靜態安全網

`npm run lint` 驗封裝、`npm test` 驗行為、`npm run build` 驗模組連結。檢查 `rg "from './app.js'" src` 應無結果。沒有 rg 可用 `git grep -F "from './app.js'" -- src`。選取狀態與 `Media._*` 的公開入口、ESLint 覆蓋規則見 [AGENTS.md](../AGENTS.md)。

## 8. 常見陷阱

查不到本機資源、mpv 被遮住、原生對話框或交付異常，看 [Electron 排查](Electron_維護手冊.md#8-排查)。字幕三路對齊、字型、Windows filtergraph 或 `[hidden]` 看[技術鐵律](技術架構說明.md#0-鐵律invariants)。核對 ASAR 先切到獨立 temp 或使用 Buffer API。禁止在 repo 根執行 `asar extract-file`，避免覆蓋 Vite 原始入口。
