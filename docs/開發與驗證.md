# SUB Tool — 開發與驗證

> **接手本專案請先讀 [`技術架構說明.md`](技術架構說明.md) 的 §0「鐵律」。** 那一節列的是
> 「違反後會【靜默】壞掉」的不變量——畫面看起來正常、匯出卻是錯的。本專案絕大多數的 bug
> 都出在那幾條上，而且每一條後面都附了真實踩雷紀錄。
>
> AI 助理另見專案根目錄的 [`AGENTS.md`](../AGENTS.md)。

本專案為 **Vite + 原生 ES 模組**（無框架），打包後輸出**單一可雙擊的 HTML**
（`vite-plugin-singlefile` 把 JS/CSS 全部內嵌），兼顧可維護性與「免安裝、點開即用」。
同一份程式碼同時跑網頁版與 Electron 桌面版（以 `window.subtool` / `IS_DESKTOP` 分支）。

---

## 1. 指令

```bash
npm install           # 第一次（安裝 Vite / Electron / vitest 等）
npm run dev           # 開發：本機伺服器 + 熱更新 (HMR)，開 http://localhost:8777
npm run build         # 打包成單一檔 dist/index.html（內嵌 JS/CSS，可直接雙擊）
npm run preview       # 預覽打包結果
npm run electron      # 打包後以 Electron 桌面版開啟
npm run electron:dev  # Electron 連 dev server（會開 DevTools，驗證用）
npm run dist          # 打包 + electron-builder 產生安裝檔 exe → release/
npm run lint          # eslint src（抓「用了沒 import 的名稱」）
npm test              # vitest run（純函式單元測試）
npm run test:watch    # vitest 監看模式
```

一般使用者：雙擊 `啟動工具.bat`（自動 build 並開啟 dist 單一檔）或
`啟動桌面版.bat`（build + Electron）。

### 前置需求

- [Node.js](https://nodejs.org) 18+
- ffmpeg / ffprobe（桌面版 MXF / 多音軌需要）：已內建於 `electron/ffmpeg/`，
  找不到時才回退系統 PATH 或 `C:\Program Files\FFMPEG\bin\`
- mpv（秒開功能，選用）：已內建於 `electron/mpv/`

## 2. 發版流程

```bash
npm run lint && npm test && npm run build   # ① 三關全綠才繼續
#                                            ② 桌面版真機驗證（見 §3、§4）
# ③ 版號只改 package.json 與 package-lock.json
# ④ docs/版本變更紀錄.md 最上面新增一筆
npm run dist                                 # ⑤ 產出 release/SUB Tool Setup X.Y.Z.exe
# ⑥ 實際安裝／啟動新 Setup，確認 app 內顯示 X.Y.Z
git add -A && git commit && git push origin main
# ⑦ 建立 GitHub Release，附上同一支 Setup .exe、tag 與面向使用者的變更說明
```

> ### ⚠ 升版時絕對不要做版號的全域字串取代
>
> 文件裡的版號有兩種：`## [v4.31.2]` 標題、「v4.27 起的安裝版才開始壞」這類**歷史事實**
> （永遠不要動），以及少數的當前版本範例。全域取代會把前者一起改掉。
>
> **真實事故**：`17aa365` 升版時對 `版本變更紀錄.md` 做了全檔取代，95 筆歷史版號一次全毀，
> 內文還出現「v5.2.0 造成、v5.2.0 修復」這種自相矛盾的句子。v5.2.0 又重演一次。
> 已於 v5.2.2 從 git 還原。
>
> **各文件標頭刻意不寫版號**——`package.json` 是唯一真相來源。

**變更紀錄請寫「為什麼」與「怎麼驗的」，不要只寫「修了 X」。** 這份檔案是本專案最有價值的
交接資產——很多坑（字型家族名、filtergraph 跳脫、CSS 蓋掉 `[hidden]`）都是靠它才沒有重踩。

> 本專案採 **main 直接發佈**。若工作樹混有未確認的修改，不能直接 `git add -A`，
> 必須先確認哪些檔案屬於這一版。**本專案由多個 AI 工具並行維護，這點特別重要**——
> 你看到的未提交變更可能不是你做的。

## 3. 真機驗證（CDP）——本專案的主要驗證手段

單元測試只涵蓋純函式（時碼、格式、工具、資料完整性）。
**UI 與媒體行為一律以 CDP 驅動真的 Electron 視窗驗證**，不靠肉眼點一點就算過。

```bash
# 用【獨立的 user-data-dir】啟動 dev electron，切勿殺掉使用者安裝的 SUB Tool.exe
electron . --remote-debugging-port=9223 --user-data-dir=<暫存目錄> \
           --disable-background-timer-throttling --disable-renderer-backgrounding \
           --disable-backgrounding-occluded-windows
# 再用 CDP 連上去 Runtime.evaluate 一段 async IIFE，操作 UI 並回傳斷言結果
```

- 前端掛有 **`window.SUB`** 除錯把手：`State / Media / Wave / SubFormats / Project`
  與各渲染函式，另有 **`window.SUB.WC`**（WebCodecs 診斷）與
  **`window.SUB.SubStyle`**（樣式系統）。驗證腳本靠它建構情境（塞 cues、切軌、觸發渲染）
  再讀回結果。
- **互動要發真事件**（CDP `Input.dispatchMouseEvent`）。`Runtime.evaluate` 造假事件
  驗不到 pointer capture／pointer-events／hit-test——事件沒接上正是重構最常見的錯。
- **背景視窗的 `setTimeout`/`rAF` 會被節流** → 一定要加上面那三個 flag，並 `Page.bringToFront()`。
- **測試必須自己處理擋路的對話框**：例如 `openCueEditModal` 會先 `await ensureProjectSaved()`，
  全新實例下會跳「開始前先儲存專案」把後續視窗擋住。不處理的話，
  「前一輪剛好把專案標記成已存檔就過、換個乾淨實例就掛」——這種看時機決定過不過的測試比沒測還危險。
- **每支測試用全新實例跑**：共用同一個 app 實例時，前一支留下的選取狀態會污染後一支。

### 兩個「驗證方法本身出錯」的案例（別再犯）

| 案例 | 當時檢查的 | 為什麼測了等於沒測 |
|------|-------------|-------------------|
| v4.33.2 預覽畫布全黑 | `getImageData` 讀得到像素、inline `style.display` 是 `''` | **隱藏的 canvas 照樣讀得到像素**；`''` 只代表沒有 inline 值，實際 computed 是 `none` |
| v4.34.1 編輯提示列藏不掉 | `el.hidden === true` | `.ts-line{display:flex}` 是作者規則，**蓋過 UA 樣式表的 `[hidden]{display:none}`**——屬性是 true，畫面上照樣看得到 |

兩次都是**改用 computed display／截圖**才發現。判斷「有沒有顯示」請用
`getComputedStyle(el).display` 或 `getBoundingClientRect().height`。
判準詳見 [`技術架構說明.md`](技術架構說明.md) §0.6「有產出不等於對」與 §0.7。

## 4. 大檔人工驗證清單

以下這批**需要真實大檔、只能人工判讀**（媒體管線、混音、FPS 一致性）。
一般功能改動請用 §3 的 CDP 自動驗證。

啟動方式（看得到錯誤，建議開兩個終端機）：

```bash
npm run dev           # 終端機 1：vite dev server
npm run electron:dev  # 終端機 2：Electron 連 dev server（自動開 DevTools）
```

> **開檔有兩條路徑**：偵測到 **mpv** 時，非原生格式或多音軌會以 mpv **秒開**
> （嵌入式覆蓋視窗播放），音軌於背景抽取；無 mpv 則走 **ffmpeg 單次讀取轉檔**（有進度 %）。
> 兩種路徑的字幕編輯與混音器行為一致。

### 4.1 MXF（MPEG-2 4:2:2 + 8 單聲道）

- 開檔後狀態列依序：`讀取媒體資訊…` →「**讀取並轉檔中（單次讀取，大檔需數分鐘）…**」+ 進度 % → `媒體已載入（桌面模式）`
- [ ] 影片畫面出得來（修正前因 4:2:2 是黑的 / 不能播）
- [ ] 🔊 音軌面板出現正確聲道數量
- [ ] 整個來源檔只被讀取「一遍」（不再是 proxy + 每軌 + 波形分開讀很多遍）

### 4.2 MOV（ProRes HQ 4:2:2 10-bit + 5.1）

- [ ] 影片能播
- [ ] 🔊 出現 6 條聲道（5.1 被 channelsplit 拆成獨立聲道）

### 4.3 混音器 🎚（時間軸工具列按鈕）

- [ ] 出現 N 條垂直電平表 + S（獨奏）/ M（靜音）
- [ ] 播放時：有內容的聲道表會跳動、無訊號的保持平的
- [ ] 表頭取「源頭訊號」：某聲道靜音時，表仍會顯示它有沒有內容

### 4.4 專案音訊路由、解除影音與純音訊時間軸

- [ ] 匯入 8 聲道素材後，專案預設至少有 8 條輸出 bus；再匯入 10 聲道素材後可擴至 10 條且既有路由不變。
- [ ] 輸出配置設為 `5.1 + Stereo` 時，bus 1–6 與 7–8 的來源範圍、混音器與匯出摘要一致；改成全部 Mono 時每條 bus 仍獨立。
- [ ] 對兩支不同影音素材分別指定來源→bus 對應，調整其中一支不會改到另一支。
- [ ] 對 MXF／MOV 執行「解除影音」：完成後有獨立音訊片段；移動、修剪與 `Ctrl+K` 切割音訊都不會動到影片，反向亦然。
- [ ] 點左側或素材片段的 `🔊`，按鈕改為 `🔇` 且播放靜音；再點一次恢復（外部音檔與影片原音都要測）。
- [ ] 刪除最後一支影片後，外部／已解除的音訊仍能在黑畫面時間軸中播放；WAV 匯出仍可選取。

### 4.5 快取秒開

- [ ] 關掉該檔、再開同一支 → 狀態列出現「**使用既有快取，秒開…**」（或「**啟動 mpv（秒開）…**」）且幾乎瞬間載入
- 快取位置（讀取時依序找第一個有效的、寫入時找第一個可寫的）：
  ① 影片同資料夾的 `.subtool_Cache` ② `%APPDATA%\sub-tool\mediacache`
- 清除：時間軸工具列的 **🗂 快取管理** 可「清理孤兒檔 / 全部清除」；或直接刪上述資料夾。
  （key = 路徑 + 大小 + 前 1MB 雜湊；來源檔內容變了會自動重轉）

### 4.6 確認用到 GPU 編碼

- DevTools console 執行：`await window.subtool.status()`
- [ ] 回傳含 `venc: "h264_nvenc"`（或 qsv / amf；否則為 `libx264`）

### 4.7 FPS / 時碼一致性

> 背景與設計原則見 [`FPS_時碼一致性.md`](FPS_時碼一致性.md)；程式關鍵點以 `FPS-SYNC` 標記。
> 建議用 **29.97fps NDF** 的長片（一小時以上）測，最容易暴露問題。

- [ ] **同格**：seek 到任一字幕起點並暫停 → 播放器大時碼 與 時間軸播放點正下方刻度的時碼**完全相同**。
- [ ] **逐格精度**：在高時碼處（如 01:20:00 之後）按 `→` 一次只前進**一格**、`←` 只後退一格。
- [ ] **刻度一致**：時間軸放大到「格」層級時，播放點所在刻度標籤 與 播放器時碼一致；字幕列表 In/Out 也同格。
- [ ] **mpv 沉降**：以 mpv 路徑開檔，seek 後暫停反覆數次 → 播放器時碼不會偶爾多/少一格。
- [ ] **（正常現象，非 bug）** 29.97 **NDF** 在長時碼處，播放器時碼會比真實經過秒數**慢幾秒**（每小時約 3.6 秒）。要時碼≈牆鐘請改用 **29.97 (DF)**。

### 4.8 空白專案基本流程

- [ ] 新專案啟動後，時間軸已有「軌道 1」（不需手動新增）
- [ ] 無影片時可拖曳播放點（播放點不卡在 0）
- [ ] 按 `I`/`O` 可在目前位置新增空白字幕並出現在時間軸
- [ ] 第一次匯入影片或字幕時，時間軸自動縮放至完整影片長度

### 4.9 專案載入

- [ ] 雙擊 `.subtool` 檔案：軟體可自動啟動並載入該專案（包含影片與字幕進度）。

### 4.10 圖片素材、監看 TC 與交付 TC

- [ ] 在已有影片的專案匯入 PNG/JPG：圖片成為最上層、預設 10 秒的片段；播放頭位於它的整段期間內時皆可見，不能只在第一格出現。
- [ ] 選取圖片後，虛線框與黃色控制點跟著**圖片本身**（不是整個畫框）；拖曳圖片可移動、拖曳角點可調整大小。鎖定視訊軌時操作被阻擋，解鎖後恢復。
- [ ] 用 mpv 路徑（例如 MXF）重做上一項：圖片外區域仍可操作字幕、安全框與播放器；拖曳期間圖片與安全框不閃爍或消失。
- [ ] 儲存專案、完全關閉程式、再開啟 `.subtool`：圖片的來源、In/Out、時間軸位置、大小與位置均保留。純圖片專案在之後再匯入第一支影片時也不能遺失。
- [ ] 匯出一段圖片位於中段或超過一秒的影片：整段都持續顯示圖片，位置與大小與播放器一致。
- [ ] 打開播放器的 `TC`：一般 HTML 預覽與 mpv 預覽都要顯示與播放器大時碼相同的讀數；關掉後不殘留框線或 TC。
- [ ] 匯出視窗勾選「壓入時間碼浮水印」：輸出檔左上角顯示由輸出 `[In]` 開始的時碼，數字等寬；未勾選時不可含 TC。WAV 匯出不可出現此選項。

### 4.11 字幕文字檢查、範圍與操作紀錄

- [ ] 文字檢查遇到常見簡體字，或日文假名／韓文／俄文／零寬空白等非允許字元時，字幕編號為紅色，hover 可看到是哪些字元。
- [ ] 繁簡共用字（「后、干、台、里」等）與台灣常用字白名單（台、裡、著、面、才、只、它…）不得誤報。
- [ ] 設定／清除播放器 `[In]`、`[Out]` 後，動作紀錄出現相應項目；`Ctrl+Z`／Redo 可還原範圍，匯出預覽起訖同步改變。
- [ ] 按住 Alt 拖曳字幕區塊：原字幕不移動，放開位置新增一份複本；一般拖曳仍為移動。
- [ ] 右鍵播放速度選「自訂速度」後能輸入並套用 0.1x–4x；取消不改變目前速度。

### 4.12 母素材匯出、音訊 bitrate 與匯出效能

- [ ] 以多聲道母素材（MXF／MOV）匯出 MP4：完成通知顯示「音訊 AAC 實測」，Mono 約 192k、Stereo 約 320k、5.1 約 640k；**不可**顯示播放快取 `chN.m4a` 的 128k。
- [ ] 配線為多條 Mono 後，以 ffprobe 檢查每條輸出 stream 的 bitrate 是本次 MP4 的 AAC 交付值，而非來源／Proxy bitrate。
- [ ] 畫面與音訊同來自同一大型素材時，觀察 ffmpeg 日誌／系統 I/O：素材應**只開啟一次**同時供影像與音訊 filtergraph 使用。
- [ ] 在匯出視窗按「聲道設定」後按取消：回到匯出視窗，且格式、MP4 Mbps 與 TC 勾選狀態仍保留。

### 4.13 軌道點選與鍵盤導航

- [ ] 點選時間軸空白處（軌道區域）：清空當前選擇，並將該軌記錄為 Active Track。
- [ ] 字幕軌模式下按 `↑`／`↓`：焦點與播放頭跳轉並選取該軌內的上一條／下一條字幕。

## 5. 出問題怎麼回報

- **DevTools console** = renderer（前端）錯誤
- **終端機 2（Electron）** = main 行程 / ffmpeg 錯誤
- 把紅字訊息貼出來即可

### 預期效能

- **第一次**開檔會等單次轉碼完成（GPU 下 MXF 約 4–5 分、MOV 約 7–12 分，主要受讀取大檔的硬碟 I/O 限制）。
- **第二次以後**同一支片由快取秒開。

### 設計上的取捨（已知、非 bug）

- 採「單次讀取 + 進度條 + 快取」，**沒有**做「轉檔途中即可編輯」（那需要 HLS 串流，會造成時間軸累積漂移 5.9–7.4 秒，對逐格字幕是大忌）。
- 單一音訊素材一次只顯示 MIX 或一條指定來源聲道的波形；這是顯示選擇，不改變專案路由或輸出。
- 聲道分組（5.1 / 2.0）無法從中繼資料可靠判斷（`channel_layout` 常為 unknown），故一律逐聲道攤開。

## 7. 架構：事件匯流排（解除與 app.js 的雙向相依）

**重點：沒有任何模組 `import … from './app.js'`。** 低階模組需要觸發「重繪 / 指令」時，
呼叫 `emit('事件名', …)`（來自 `events.js`），**不直接 import 渲染函式**。`app.js` 於啟動時以
`on('事件名', 處理函式)` 訂閱。`emit` 為**同步**呼叫，語意與直接呼叫原函式完全一致。

目前的事件：

```
render:all          → renderAll             render:videoSub    → renderVideoSub
render:listTrackSel → renderListTrackSel    render:trackStyle  → renderTrackStyle
playhead:ensure     → ensurePlayheadVisible duration:known     → onDurationKnown
mpv:refreshSubs     → refreshMpvSubs        mpv:sync           → mpv 時鐘同步
panel:toggle        → togglePanel(id)       note:openInPanel   → openNoteInPanel(n)
cue:openEdit        → openCueEditModal(c)   fps:changed        → FPS 變更後重繪
history:record      → recordHistory(label)  action             → doAction(act)
audio:projectRestored → 還原後重建音訊 runtime
audio:externalRestored → media.js 訂閱（非 app.js）：重建外部音訊素材
```

> ⚠ `audio:busChanged`（`mixer.js` emit）目前**沒有任何訂閱者**。`events.js` 的 `emit`
> 在無 handler 時是靜默 no-op，所以不會報錯——加訂閱者或移除該 emit 前，不要假設它有作用。

其餘跨模組相依改為「就近直接 import」而非繞經 app.js：基本 UI 一律
`import … from './ui.js'`；磁吸工具定義在 `timeline.js`；`detectFpsWeb` 定義在 `media.js`。

**維護守則：不要再新增 `import … from './app.js'`。** 需要 app.js 協調的動作，請改用
`emit(...)`，並在 app.js 的訂閱區補一行 `on(...)`。

## 9. 常見陷阱（改之前先知道）

- **Electron 停用了 `window.prompt()`**——用會靜默失敗（使用者按了「沒反應」）。要輸入請用
  `ui.js` 的 `promptModal()`。
- **`file://` 的 `@font-face { src:url(...) }` 會被 Chromium 擋**（"A network error occurred"），
  即使關掉 webSecurity 也一樣 → 字型必須用 **FontFace API + ArrayBuffer** 註冊。
- **mpv 是 OS 層的 always-on-top 視窗**，蓋在所有 HTML 之上 → 任何 HTML 疊層（字幕拖曳層、
  安全框）在 mpv 模式下都看不到也點不到，必須先讓 mpv 讓位。
- **預設值不要寫在兩個地方**：字級預設值曾同時存在於 `STYLE_DEFAULTS` 與 `newTrack()`，
  改一個忘了另一個。
- CSS 的**作者規則會蓋過 UA 樣式表的 `[hidden]`**——要用 `el.hidden` 藏一個有 `display:` 的
  元素，得自己補 `.那個class[hidden]{display:none}`。
- **「同一列」不要用盒頂座標比**——不同高度的元素垂直置中後盒頂本來就不同（分隔線 15px vs
  下拉 23px 差 4px）。比**垂直中心**，或量整行高度確認沒換行。
