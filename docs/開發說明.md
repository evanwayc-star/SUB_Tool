# SUB Tool — 開發 / 建置說明

> 對應版本：v4.6.3｜最後更新：2026-07-23
>
> **接手本專案請先讀 [`技術架構說明.md`](技術架構說明.md) 的 §0「鐵律」。** 那一節列的是
> 「違反後會【靜默】壞掉」的不變量——畫面看起來正常、匯出卻是錯的。本專案絕大多數的 bug
> 都出在那幾條上，而且每一條後面都附了真實踩雷紀錄。

本專案為 **Vite + 原生 ES 模組**（無框架），打包後輸出**單一可雙擊的 HTML**
（`vite-plugin-singlefile` 把 JS/CSS 全部內嵌），兼顧可維護性與「免安裝、點開即用」。
同一份程式碼同時跑網頁版與 Electron 桌面版（以 `window.subtool` / `IS_DESKTOP` 分支）。

## 指令

```bash
npm install           # 第一次（安裝 Vite / Electron / vitest 等）
npm run dev           # 開發：本機伺服器 + 熱更新 (HMR)，開 http://localhost:8777
npm run build         # 打包成單一檔 dist/index.html（內嵌 JS/CSS，可直接雙擊）
npm run preview       # 預覽打包結果
npm run electron      # 打包後以 Electron 桌面版開啟
npm run electron:dev  # Electron 連 dev server（會開 DevTools，驗證用）
npm run dist          # 打包 + electron-builder 產生安裝檔 exe → release/
npm run lint          # eslint src（抓「用了沒 import 的名稱」）
npm test              # vitest run（純函式單元測試）
npm run test:watch    # vitest 監看模式
```

一般使用者：雙擊 `啟動工具.bat`（自動 build 並開啟 dist 單一檔）或
`啟動桌面版.bat`（build + Electron）。

## 發版流程（每次改完都照這個順序走）

```bash
npm run lint && npm test && npm run build   # ① 三關全綠才繼續
#                                            ② 桌面版真機驗證（見下節）
# ③ package.json 與 package-lock.json 版號同步 +1
# ④ README.md 與 docs/ 全部同步；docs/版本變更紀錄.md 必須寫改了什麼、為什麼、驗證方式
npm run dist                                 # ⑤ 產出 release/SUB Tool Setup X.Y.Z.exe
# ⑥ 實際安裝／啟動新 Setup，確認 app 內顯示 X.Y.Z
git add -A && git commit && git push origin main
# ⑦ 建立 GitHub Release，附上同一支 Setup .exe、tag 與面向使用者的變更說明
```

> 此專案目前採 **main 直接發佈**；若工作樹混有未確認的使用者修改，不能直接 `git add -A`，必須先確認哪些檔案屬於這一版。

**變更紀錄請寫「為什麼」與「怎麼驗的」，不要只寫「修了 X」。** 這份檔案是本專案最有價值的
交接資產——很多坑（字型家族名、filtergraph 跳脫、CSS 蓋掉 `[hidden]`）都是靠它才沒有重踩。

## 真機驗證（CDP）——本專案的主要驗證手段

單元測試只涵蓋純函式（時碼、格式、工具）。**UI 與媒體行為一律以 CDP 驅動真的 Electron
視窗驗證**，不靠肉眼點一點就算過。

```bash
# 開一個帶 remote debugging 的 Electron（用獨立 user-data-dir，不污染正式設定）
electron . --remote-debugging-port=9223 --user-data-dir=<暫存目錄> \
           --disable-background-timer-throttling --disable-renderer-backgrounding
# 再用 CDP 連上去 Runtime.evaluate 一段 async IIFE，操作 UI 並回傳斷言結果
```

- 前端在 dev build 會掛上 **`window.SUB`** 除錯把手（正式 build 自動移除）：
  `State / Media / Wave / SubFormats / Project` 與各渲染函式，另有
  **`window.SUB.WC`**（WebCodecs 診斷）與 **`window.SUB.SubStyle`**（樣式系統）。
  驗證腳本就是靠它建構情境（塞 cues、切軌、觸發渲染）再讀回結果。
- **一定要模擬真的事件**（`dispatchEvent(new Event('input',{bubbles:true}))`、
  `el.click()`），不要直接改 State 就宣稱「UI 有接上」——事件沒接上正是重構最常見的錯。
- **「有沒有顯示」一律看 computed style 或量到的尺寸**，不要看屬性值。這條是血淚，見
  §0.6 與下面兩個真實案例。

### 兩個「驗證方法本身出錯」的案例（別再犯）

| 案例 | 我當時檢查的 | 為什麼測了等於沒測 |
|------|-------------|-------------------|
| v4.33.2 預覽畫布全黑 | `getImageData` 讀得到像素、inline `style.display` 是 `''` | **隱藏的 canvas 照樣讀得到像素**；`''` 只代表沒有 inline 值，實際 computed 是 `none` |
| v4.34.1 編輯提示列藏不掉 | `el.hidden === true` | `.ts-line{display:flex}` 是作者規則，**蓋過 UA 樣式表的 `[hidden]{display:none}`**——屬性是 true，畫面上照樣看得到 |

兩次都是**改用 computed display／截圖**才發現。判斷「有沒有顯示」請用
`getComputedStyle(el).display` 或 `getBoundingClientRect().height`。

## 架構：事件匯流排（解除與 app.js 的雙向相依）

**重點：沒有任何模組 `import … from './app.js'`。** 低階模組需要觸發「重繪 / 指令」時，
呼叫 `emit('事件名', …)`（來自 `events.js`），**不直接 import 渲染函式**。`app.js` 於啟動時以
`on('事件名', 處理函式)` 訂閱。`emit` 為**同步**呼叫，語意與直接呼叫原函式完全一致。

目前的事件：

```
render:all          → renderAll             render:videoSub    → renderVideoSub
render:listTrackSel → renderListTrackSel    render:trackStyle  → renderTrackStyle
playhead:ensure     → ensurePlayheadVisible duration:known     → onDurationKnown
mpv:refreshSubs     → refreshMpvSubs        mpv:sync           → mpv 時鐘同步
panel:toggle        → togglePanel(id)       note:openInPanel   → openNoteInPanel(n)
cue:openEdit        → openCueEditModal(c)   fps:changed        → FPS 變更後重繪
history:record      → recordHistory(label)  action             → doAction(act)
```

其餘跨模組相依改為「就近直接 import」而非繞經 app.js：基本 UI 一律
`import … from './ui.js'`；磁吸工具定義在 `timeline.js`；`detectFpsWeb` 定義在 `media.js`。

**維護守則：不要再新增 `import … from './app.js'`。** 需要 app.js 協調的動作，請改用
`emit(...)`，並在 app.js 的訂閱區補一行 `on(...)`。

## 靜態安全網

- `npm run lint`：抓「使用了未匯入的名稱」(no-undef)。
- `npm run build`：rollup 會抓「import 了某模組未 export 的名稱」（eslint 抓不到 export 端）。
- 確認沒有重新引入循環：`grep -rn "from './app.js'" src` 應為**空**。

## 常見陷阱（改之前先知道）

- **Electron 停用了 `window.prompt()`**——用會靜默失敗（使用者按了「沒反應」）。要輸入請用
  `ui.js` 的 `promptModal()`。
- **`file://` 的 `@font-face { src:url(...) }` 會被 Chromium 擋**（"A network error occurred"），
  即使關掉 webSecurity 也一樣 → 字型必須用 **FontFace API + ArrayBuffer** 註冊。
- **mpv 是 OS 層的 always-on-top 視窗**，蓋在所有 HTML 之上 → 任何 HTML 疊層（字幕拖曳層、
  安全框）在 mpv 模式下都看不到也點不到，必須先讓 mpv 讓位。
- **預設值不要寫在兩個地方**：字級預設值曾同時存在於 `STYLE_DEFAULTS` 與 `newTrack()`，
  改一個忘了另一個。
- CSS 的**作者規則會蓋過 UA 樣式表的 `[hidden]`**——要用 `el.hidden` 藏一個有 `display:` 的
  元素，得自己補 `.那個class[hidden]{display:none}`。
